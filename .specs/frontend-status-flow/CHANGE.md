# CHANGE: 文件处理状态流前端实时展示

- **Change ID**: `frontend-status-flow`
- **创建日期**: 2026-06-22
- **路径建议**: 最短（`REQUIREMENT (增量) → TASK → DEV`，纯前端修复 + 轻量增强，无需独立 DESIGN 和 ADR）
- **状态**: draft

---

## Why（为什么做）

文件处理后端管线（`UPLOADED → PARSING → PARSED → EXTRACTING → EXTRACTED → FUSING → COMPLETED`）已有完整状态机，但前端轮询机制存在缺陷 + 展示层薄弱，导致用户无法感知文件在 `PARSED` 之后的状态变化。

**具体痛点**：

1. **轮询覆盖范围不足**：`fileStore.ts` 中 `INTERMEDIATE_STATES` 仅含 `['UPLOADED', 'PARSING']`，一旦解析完成进入 `PARSED`，前端立即停止轮询。后续 `EXTRACTING → EXTRACTED → FUSING → COMPLETED` 四个阶段（异步执行，可能耗时数十秒到数分钟）前端完全无感知，用户看到文件卡在「已解析」无法判断图谱构建是否在进行或已完成
2. **轮询空转隐患**：当前 `UPLOADED` 被纳入中间态，若 `parseFile()` 调用失败或用户上传后不点解析，文件长期停留 `UPLOADED` 导致轮询永不停止（空转）
3. **状态展示形式单一**：仅用一个 `StatusBadge` 徽章展示当前状态文字，用户无法直观理解文件处理走到了管线的哪一步、还剩几步
4. **图谱可视化页无状态感知**：文档选择器过滤出已抽取文档，但不展示处理进度；用户选中文档后无法知道图谱数据是否已是最新（例如文档正在 `FUSING` 中，子图数据可能不完整）

## What（做什么）

1. **修复轮询策略（核心修复）**：
   - `INTERMEDIATE_STATES` 改为仅包含活跃处理态：`['PARSING', 'EXTRACTING', 'FUSING']`
   - 移除 `UPLOADED`（稳定态，当前已有 bug：parse 失败时轮询永不停止）
   - 增加**最大轮询时长**（默认 5 分钟），超时自动停止，防止异常情况空转
   - 轮询仅在用户主动触发处理（上传/解析）后开启，不在页面挂载时无条件启动
2. **管线进度可视化**：新增/增强状态展示组件，显示完整处理管线（上传 → 解析 → 抽取 → 融合 → 完成），高亮当前所处阶段，让用户一眼看清进度
3. **图谱页状态联动**：文档选择器中展示文档当前处理状态，处理中的文档标注进度；子图数据加载后若文档状态非终态给出提示

## 范围排除（这次不做）

- 后端状态机变更（状态枚举、流转规则、事件机制均不变）
- WebSocket/SSE 实时推送（V1 继续使用轮询，V2 可升级但不在本次范围）
- 文件处理管线可暂停/可恢复/可取消（超出 V1 范围）
- 成绩文件的处理状态流（成绩无异步管线，上传即完成）
- 智能问答的异步任务状态流（已有独立的任务状态轮询机制，`QueryTaskStatus`）
- 图谱可视化页面的深色模式或其他 UI 变更
- 轮询策略的后端性能优化（本次仅改前端轮询范围，轮询频率不变）

## 验收线（粗粒度，不是 AC）

1. 用户上传文件并触发处理后，能在文件列表中**持续看到状态变化**（上传 → 解析中 → 已解析 → 抽取中 → 已抽取 → 融合中 → 已完成），不再卡在「已解析」；处理完成后轮询自动停止，无空转
2. 文件列表的状态列展示**管线进度**（当前阶段 + 已完成/未完成阶段一目了然），而非仅文字徽章
3. 图谱可视化页的文档选择器中能看到文档处理状态，处理中的文档不可选或给出提示

## 风险与未知

- **轮询频率与空转防护**：当前 2 秒轮询一次。本次设计要点：① 仅对 `*ING` 活跃态轮询（排除 `UPLOADED` 等稳定态）；② 最大轮询时长 5 分钟兜底（LLM 抽取 + 融合通常 < 3 分钟，5 分钟留有裕量）；③ 仅在上传/手动解析后启动轮询，不在页面挂载时无条件启动。后续若文件量增长可改为按 `documentId` 单文件状态查询替代全量列表拉取
- **管线进度组件在表格行内的空间**：当前文件列表表格宽度有限（状态列 120px），完整管线步骤条可能放不下。需要在 REQUIREMENT/UI-DESIGN 阶段设计紧凑方案（如截断 + hover 展开、或替换为 mini 步骤指示器）
- **图谱页文档选择器选项数量**：当前 `loadDocuments()` 拉 100 条文件。若文件数量持续增长，需加分页或搜索；不在本次范围
