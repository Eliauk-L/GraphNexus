## 用户故事

- **US-1**：作为管理员，我想**上传 PDF 教辅和 CSV 成绩文件**，以便将教学资料和考试数据导入系统。
- **US-2**：作为管理员，我想**查看文件列表并跟踪处理状态**，以便知道哪些文件已就绪可供后续使用（如 PDF 解析、图谱抽取）。
- **US-3**：作为管理员，我想**按考试编号查看学生成绩**，以便快速检查某次考试的数据完整性。
- **US-4**：作为管理员，我想**用自然语言提问（如"分析张三数学薄弱点"）**，以便获得 LLM 生成的 Markdown 诊断报告。
- **US-5**：作为管理员，我想**查看文档的知识图谱子图**，以便直观理解文档中知识点之间的关联关系。
- **US-6**：作为管理员，我想**手动触发宽图谱融合并查看融合状态**，以便在导入多源数据后整合知识点。
- **US-7**：作为管理员，我想**查看图指标（PageRank / 度中心性）**，以便识别图谱中的核心枢纽知识点。

## 验收准则（AC）

### AC-1 · 页面框架与导航

- **Given** 用户打开浏览器访问系统 URL
- **When** 页面加载完成
- **Then** 显示左侧导航栏（含 6 个模块入口：文件管理、图谱可视化、成绩管理、智能问答、融合管理、图指标），右侧内容区默认展示文件管理页；导航切换时内容区随之更新，当前页高亮
- **验证方式**: 浏览器手动操作，点击每个导航项确认内容区切换

### AC-2 · 上传 PDF 文件

- **Given** 用户在文件管理页
- **When** 用户选择 PDF 文件、填写学科名称、点击上传
- **Then** 页面显示上传成功，文件列表中出现新记录（状态为 UPLOADED）
- **验证方式**: 选择一个 `.pdf` 文件，学科填"数学"，上传后在列表中确认出现

### AC-3 · 上传 CSV 成绩文件

- **Given** 用户在文件管理页
- **When** 用户选择 CSV 成绩文件、填写学科名称、点击上传
- **Then** 页面显示上传成功，返回考试编号、导入学生数、试题数、知识点列表
- **验证方式**: 选择一个合法 CSV 文件，学科填"数学"，上传后确认返回结果

### AC-4 · 文件列表分页浏览

- **Given** 系统中已存在 ≥ 11 条文件记录
- **When** 用户进入文件管理页
- **Then** 默认显示第 1 页 10 条记录；可翻页切换；列表每行显示：文件名、学科、文件大小、状态（中文映射：UPLOADED=已上传/PROCESSING=处理中/COMPLETED=已完成/FAILED=失败）、上传时间
- **验证方式**: 进入页面确认默认分页，点击下一页确认数据切换

### AC-5 · 触发文档解析

- **Given** 文件列表中存在状态为 UPLOADED 的 PDF 文件
- **When** 用户点击该文件的「解析」按钮
- **Then** 文件状态变为 PROCESSING → 解析完成后自动刷新为 COMPLETED（或 FAILED），显示页数和文本内容预览
- **验证方式**: 点击解析按钮，等待完成后确认状态变化

### AC-6 · 删除文件

- **Given** 文件列表中存在一条文件记录
- **When** 用户点击该文件的「删除」按钮并确认
- **Then** 该文件从列表中消失，再次查询不出现
- **验证方式**: 删除后刷新列表确认记录消失

### AC-7 · 按考试编号查询成绩

- **Given** 系统中已导入考试编号为 `E20200041` 的成绩数据
- **When** 用户在成绩管理页输入考试编号 `E20200041` 并查询
- **Then** 表格展示该考试下所有学生的成绩列表，含：学号、姓名、班级、总分、排名、各题得分明细
- **验证方式**: 输入已知考试编号，确认表格数据完整展示

### AC-8 · 智能问答 — 对话模式

- **Given** 系统已导入学生张三的数学考试数据并完成融合
- **When** 用户在智能问答页输入"分析一下张三最近数学怎么样"并提交
- **Then** 页面展示 LLM 返回的 Markdown 格式诊断报告（含标题、列表、薄弱点分析），同时显示 Token 用量（剪枝节点数/边数/估算 token）
- **验证方式**: 提交问题后确认返回 Markdown 渲染后的报告内容，含 token 统计

### AC-9 · 智能问答 — 异步轮询

- **Given** 用户提交了一个复杂问题
- **When** 系统判断耗时较长 → 返回 taskId 并显示「分析中…」状态
- **Then** 页面每 1-2 秒轮询结果，完成后自动展示 Markdown 报告；失败时展示错误信息
- **验证方式**: 提交可能超时的问题，观察轮询状态变化直到完成

### AC-10 · 文档子图可视化

- **Given** 某文档已完成知识图谱抽取
- **When** 用户在图谱可视化页选择该文档并查看
- **Then** 画布渲染节点-边图：KnowledgePoint 节点可区分显示，边按类型用不同颜色/线型标注，支持缩放和拖拽
- **验证方式**: 选择已抽取文档，确认画布渲染出连通图，拖拽/滚轮缩放正常

### AC-11 · 剪枝子图可视化

- **Given** 用户已通过智能问答获得一份诊断报告
- **When** 用户在报告页点击「查看子图」
- **Then** 跳转到图谱可视化页，渲染该次问答剪枝出的子图（含节点 properties 详情浮窗、边权重标注、剪枝元信息面板）
- **验证方式**: 问答完成后点击查看子图，确认节点悬浮显示属性，面板显示策略名/阈值等元信息

### AC-12 · 触发全量融合

- **Given** 系统中存在未融合的知识点数据
- **When** 用户在融合管理页点击「执行全量融合」
- **Then** 显示融合进行中状态，完成后返回合并 KP 组数 + MASTERS 边数；融合期间再次点击提示"操作进行中"
- **验证方式**: 点击执行融合，确认返回结果数据；快速双击确认拒绝并发

### AC-13 · 查看融合状态与回滚

- **Given** 系统至少执行过一次融合
- **When** 用户进入融合管理页
- **Then** 展示最近一次融合的详细信息（触发方式、时间、合并 KP 数、MASTERS 边数、是否已回滚）；提供「回滚」按钮
- **验证方式**: 进入页面确认信息展示，点击回滚确认操作执行

### AC-14 · 图指标查询

- **Given** 图谱中存在节点和边数据
- **When** 用户在图指标页选择指标类型（PageRank / 度中心性），可选填节点/边类型过滤
- **Then** 表格展示结果列表（节点 ID、类型、指标名、数值），按数值降序排列
- **验证方式**: 查询 PageRank 默认全图，确认返回排序后的列表

## 范围切分

### v1（本次必做）

- 页面框架：左侧导航 + 右侧内容区，6 模块入口
- 文件管理：上传（PDF/CSV）、列表分页、单条详情、触发解析、删除
- 成绩管理：按考试编号查询、删除
- 智能问答：对话模式（`POST /chat`）+ 异步轮询（`POST /ask-async` + `GET /result`）+ Markdown 渲染 + Token 用量展示
- 图谱可视化：文档子图渲染（力导向布局、缩放拖拽、边类型颜色区分）
- 融合管理：触发融合 + 查看状态 + 回滚
- 图指标：PageRank + 度中心性表格展示

### v2（下一轮考虑，不本次）

- 文件解析进度实时刷新（WebSocket 或轮询）
- 剪枝子图可视化（问答 → 查看子图联动跳转）
- 融合审计 JSON 的可视化展开（fusionDetailJson / mastersSnapshotJson）
- 图指标按节点/边类型过滤的交互式选择器（下拉多选）
- 同步问答模式（`POST /ask`，需手动填学生信息，交互更重）
- 文件名称编辑
- 批量删除

### out（永远不做）

- 学生端/家长端界面
- 移动端适配（响应式仅保证桌面 ≥1280px）
- 实时通知推送（WebSocket）
- 国际化（i18n）
- 深色模式
- 自定义仪表盘/拖拽布局
- 登录/注册/权限管理页面（后端 Spring Security 临时放开）

## 非功能性需求

- **性能**: 首屏 LCP ≤ 2.5s；路由切换 ≤ 200ms；图可视化 ≥ 200 节点时帧率 ≥ 30fps
- **可访问性**: 无硬性 WCAG 要求；表单必填项标注 `*`，按钮有明确的 hover/focus 样式
- **安全**: V1 跳过鉴权（内网部署）；CSV/PDF 上传限制 ≤ 50MB
- **兼容性**: Chrome 120+、Firefox 120+、Edge 120+（桌面端，≥1280px 宽度）
- **可观测性**: API 调用异常在 console 输出错误日志（含 traceId）；页面级异常由全局 ErrorBoundary 捕获并显示友好提示

## 依赖与假设

- **后端 API**：所有 20 个端点已实现且可用（见 CHANGE.md 后端 API 清单），假设前端开发期间端点 URL 和响应结构不发生变化
- **Swagger UI**：`/swagger-ui.html` 可访问，作为前端开发期间的主要接口参考
- **Vite proxy**：开发环境通过 Vite `server.proxy` 将 `/api` 转发到后端 `localhost:8080`
- **包重构已提交**：假设 `main` 分支上当前的 50+ 未提交变更将在前端开工前完成 commit
- **图可视化库**：不在此阶段决策，留到 DESIGN 阶段选型
- **测试数据**：假设开发环境（podman）中已有 Neo4j 图谱数据 + MySQL 文档/成绩数据可供前端联调
