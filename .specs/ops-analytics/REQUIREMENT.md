# REQUIREMENT: 运营管理 — 系统使用量、文档处理量、图谱节点/边分布统计

- **Change ID**: `ops-analytics`
- **关联**: `@.specs/ops-analytics/CHANGE.md`、`@.specs/CONTEXT.md`

---

## 用户故事

- **US-1**：作为 ADMIN 或 OPS_MANAGER，我想在运营仪表盘中查看系统使用量统计（活跃用户数、登录次数、操作频次、API 调用量），以便了解系统被谁、多频繁地使用。
- **US-2**：作为 ADMIN 或 OPS_MANAGER，我想查看文档处理量统计（总量、按状态/学科分布、处理耗时、上传趋势），以便评估文档处理效率和资源利用情况。
- **US-3**：作为 ADMIN 或 OPS_MANAGER，我想查看知识图谱节点和边的分布（按类型、按学科），以便了解图谱的组成结构和增长态势。
- **US-4**：作为 ADMIN 或 OPS_MANAGER，我想切换到不同时间粒度（天/周/月）查看所有统计指标的历史趋势，以便分析系统运营的变化规律。
- **US-5**：作为系统，我想在用户登录和关键操作发生时自动记录操作事件（含操作人、操作类型、时间），以便运营统计可以基于这些记录进行汇总计算。
- **US-6**：作为系统，我想每日自动采集并持久化关键统计指标的快照，以便历史趋势查询不依赖于原始业务数据的保留状态。

## 验收准则（AC）

### 运营仪表盘

#### AC-1 · 导航入口可见

- **Given** 用户已登录且角色为 ADMIN 或 OPS_MANAGER
- **When** 用户打开系统主界面
- **Then** 左侧导航栏显示「运营管理」菜单项，位于既有导航菜单同级，点击后进入运营仪表盘页面
- **验证方式**: 分别以 ADMIN 和 OPS_MANAGER 身份登录，检查导航栏是否出现入口并正确跳转

#### AC-2 · 非授权角色不可见

- **Given** 用户已登录且角色不是 ADMIN 也不是 OPS_MANAGER（如 TEACHER）
- **When** 用户打开系统主界面
- **Then** 左侧导航栏不显示「运营管理」菜单项，直接访问运营管理相关 URL 返回 403
- **验证方式**: 以 TEACHER 身份登录，确认菜单无入口，直接访问 `/ops` 路径返回 403

#### AC-3 · 系统使用量统计面板

- **Given** 系统中存在至少 30 天的用户操作数据（登录记录、文档操作、问答操作）
- **When** ADMIN 或 OPS_MANAGER 进入运营仪表盘页面
- **Then** 页面展示「系统使用量」区域，包含：
  - 活跃用户数（统计周期内的独立登录用户数）
  - 总登录次数（统计周期内的登录事件总数）
  - 智能问答次数（统计周期内的问答任务总数）
  - 按操作类型的分布饼图（登录 / 文档上传 / 智能问答 等类别占比）
- **验证方式**: 手动核对：`SELECT COUNT(DISTINCT user_id) FROM audit_log WHERE ...` 与页面展示数值一致

#### AC-4 · 文档处理量统计面板

- **Given** 系统中存在不同状态和学科的文档记录
- **When** ADMIN 或 OPS_MANAGER 进入运营仪表盘页面
- **Then** 页面展示「文档处理量」区域，包含：
  - 文档总量数字卡片
  - 按处理状态的分布（UPLOADED / PARSING / PARSED / EXTRACTING / EXTRACTED / FUSING / COMPLETED / FAILED）以柱状图展示
  - 按学科的文档数量分布（柱状图或饼图）
  - 选定时间范围内的上传趋势折线图
- **验证方式**: 与 `document` 表直接查询结果比对，误差为 0

#### AC-5 · 图谱节点/边分布面板

- **Given** Neo4j 图谱中存在多种类型的节点和边
- **When** ADMIN 或 OPS_MANAGER 进入运营仪表盘页面
- **Then** 页面展示「图谱分布」区域，包含：
  - 按节点类型（Entity / KnowledgePoint / KnowledgeCategory / Subject / Student / Exam）的计数，以柱状图展示
  - 按边类型（ALIGNED_TO / PREREQUISITE_OF / TESTED / MASTERS / BELONGS_TO_SUBJECT / CHILD_OF / 等）的计数，以柱状图展示
  - 学科选择器下拉框，切换后以上两类图表仅显示选中学科下的节点和边数据
- **验证方式**: 在 Neo4j Browser 中执行 `MATCH (n) RETURN labels(n)[0] AS type, count(n)` 比对页面数据

### 操作审计日志

#### AC-6 · 登录事件自动记录

- **Given** 一个用户账号存在于系统中
- **When** 用户成功登录（调用 `/api/v1/auth/login` 并返回 200）
- **Then** 系统自动记录一条操作事件，包含：操作人 ID、操作类型 = "LOGIN"、操作时间戳。该记录可在后续的运营统计查询中被汇总计入登录次数
- **验证方式**: 登录成功后查询操作记录，验证存在对应 LOGIN 事件；再次查看仪表盘时登录次数 +1

#### AC-7 · 关键业务操作自动记录

- **Given** 用户已登录
- **When** 用户执行以下任一操作：上传文档、触发文档解析、发起智能问答
- **Then** 系统自动记录一条操作事件，包含：操作人 ID、操作类型（DOCUMENT_UPLOAD / DOCUMENT_PROCESS / QA_ASK）、操作时间戳
- **验证方式**: 依次执行上述操作，每步完成后验证对应操作事件已持久化

#### AC-8 · 操作记录写入不影响主流程

- **Given** 用户正在执行登录或上传文档等操作
- **When** 操作记录写入失败（如数据库暂时不可用）
- **Then** 主操作（登录 / 上传 / 问答）仍正常完成，不因审计日志写入失败而报错或阻塞。失败信息记录到 WARN 级别日志
- **验证方式**: 模拟审计日志存储不可用（如暂停 MySQL），执行登录操作仍成功；检查日志有 WARN 记录

### 统计快照

#### AC-9 · 每日统计快照自动生成

- **Given** 系统正常运行超过 24 小时
- **When** 到达每日快照触发时间（可配置，默认凌晨 2:00）
- **Then** 系统自动采集以下指标并持久化为一条快照记录：日期、活跃用户数、登录次数、各操作类型次数、文档总量及按状态分布、图谱各节点类型计数、图谱各边类型计数、按学科的节点/边分布
- **验证方式**: 在快照时间后查询快照记录，验证昨日快照已生成且各指标字段非空

#### AC-10 · 历史趋势图表

- **Given** 快照表中已有 ≥ 7 天的连续快照数据
- **When** ADMIN 或 OPS_MANAGER 在运营仪表盘中选择时间粒度（天/周/月）和时间范围
- **Then** 各统计区域的历史趋势图表基于快照数据渲染：
  - 折线图展示选定范围内每个时间点的指标数值
  - 切换时间粒度后，图表按新粒度聚合重新渲染
  - 无快照数据的日期显示为空或标注"无数据"
- **验证方式**: 选择最近 7 天，折线图上应有 7 个数据点，数值与快照表中对应条目一致

#### AC-11 · 实时面板与历史趋势共存

- **Given** 系统既有实时数据也有历史快照数据
- **When** 用户打开运营仪表盘
- **Then** 数字卡片显示的是当前实时值（如当前图谱节点总数）；趋势图表基于历史快照数据展示变化曲线；两种数据来源在 UI 上有清晰区分（如卡片标注"当前"、图表标注"历史趋势"）
- **验证方式**: 卡片数值与实时查询结果一致；图表数值与快照表一致

### 访问控制

#### AC-12 · 后端端点角色保护

- **Given** 运营统计 API 端点已部署
- **When** 非 ADMIN 且非 OPS_MANAGER 角色的用户请求运营统计相关 API
- **Then** 返回 HTTP 403，响应体包含错误码 A0013（权限不足）
- **验证方式**: 以 TEACHER 身份调用运营统计 API，验证 403 + A0013

#### AC-13 · 前端菜单角色过滤

- **Given** 前端已集成角色权限判断逻辑
- **When** 非 ADMIN/OPS_MANAGER 用户登录后进入任意页面
- **Then** 左侧导航栏不渲染「运营管理」菜单项，用户无法通过 UI 导航进入运营仪表盘
- **验证方式**: 以 TEACHER 身份登录，检查导航栏 DOM，确认无"运营管理"节点

## 范围切分

### v1（本次必做）

- 操作审计日志（登录 + 文档上传 + 文档处理 + 智能问答的自动记录）
- 运营仪表盘页面：系统使用量、文档处理量、图谱分布三大区域
- 每个区域含：数字统计卡片 + 图表（饼图/柱状图/折线图）
- 时间粒度切换：天 / 周 / 月
- 图谱分布支持按学科过滤
- 每日统计快照自动采集
- 历史趋势折线图（基于快照数据）
- 实时面板与历史趋势在 UI 上区分标注
- 角色访问控制：ADMIN + OPS_MANAGER 可见
- 前端导航栏新增「运营管理」一级菜单
- 后端统计 API 端点权限保护

### v2（下一轮考虑，不本次）

- 统计报表导出（PDF / Excel 格式）
- 指标异常告警与通知（如"文档处理失败率 > X% 触发通知"）
- 图谱节点级详情钻取（从分布图点击跳转到节点列表页）
- 实时数据推送（WebSocket 自动刷新，替代页面手动轮询）
- 自定义时间范围选择器（在 天/周/月 之外支持起止日期自由选择）
- 操作审计日志的高级筛选与搜索（按用户/操作类型/时间范围检索审计日志列表）

### out（永远不做）

- 多租户/学校级数据隔离（v1 为全系统统计，项目无多租户需求）
- 细粒度字段变更审计（如"用户 A 将文档标题从 X 改为 Y"，不属于运营统计范畴）
- 面向学生/家长的运营数据暴露（运营数据仅内部管理使用）

## 非功能性需求

- **性能**: 运营仪表盘页面首屏加载（含所有实时统计查询 + 图表渲染）≤ 3 秒；单个图表数据查询 ≤ 1 秒
- **安全**: 运营统计 API 仅 ADMIN 和 OPS_MANAGER 角色可访问；统计响应体不含个人可识别信息（PII）——不暴露具体用户的操作明细，仅展示聚合数值
- **可访问性**: 图表需提供等价的文字描述或表格形式，确保屏幕阅读器可获取关键数据（图表旁提供"查看数据表格"链接）
- **兼容性**: 桌面端 ≥ 1280px 宽度（与项目 V1 目标分辨率一致），不支持移动端
- **可观测性**: 审计日志写入失败时落 WARN 日志（含操作人 + 操作类型 + 失败原因）；快照采集失败时落 ERROR 日志（含失败步骤和异常堆栈）；统计 API 响应时间 > 2s 时落 WARN 日志

## 依赖与假设

- **依赖内部模块**: `user-auth-rbac`（角色模型与 `@PreAuthorize` 注解）、既有 `document` 表（文档统计数据源）、`query_task` 表（问答统计数据源）、Neo4j 图谱（节点/边分布数据源）
- **依赖基础设施**: MySQL（审计日志表 + 快照表）、Neo4j（图谱统计查询）
- **依赖前端**: 项目既有 Vue 3 + TypeScript + Vite 技术栈、Pinia 状态管理、极简设计语言
- **假设**: 项目将引入定时任务调度机制（当前未使用），具体方案由 DESIGN 阶段选型（Spring `@Scheduled` / Quartz / XXL-JOB）
- **假设**: 前端图表库由 DESIGN 阶段选型，需兼容 Vue 3 且支持柱状图、折线图、饼图三种基础图表类型
- **假设**: 操作审计日志采用异步非阻塞写入方式，不拖慢主业务流程
