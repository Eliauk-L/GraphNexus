# K12-KGraph 单册：BERT-BiLSTM-CRF 与 CasRel 构图最小可行性方案

状态：设计方案；尚未标注数据、训练模型或执行评测。本文中的“CRT”按“CRF（条件随机场）”理解。

## 1. 目标与边界

使用同版次人教版七年级数学上册的解析文本，验证一条可运行、可对照的非大模型构图路线：

1. 中文 BERT + BiLSTM + CRF 从教材原文识别知识点名称。
2. 中文 BERT + CasRel 从有明确句级证据的教材原文抽取有向先修三元组。
3. 对抽取结果做名称归一、去重和端点关联，形成 GraphNexus 的 `CandidateGraph`。
4. 与当前规则抽取流水线在同一测试范围内比较知识点和先修边质量。

评测范围沿用[单册最小评测与对照实验实施方案](./K12-KGraph单册最小评测与对照实验实施方案.md)：只纳入 K12-KGraph 样例图中的 `Concept`、`Skill` 节点，以及两端均在这些节点中的 `prerequisites_for` 有向边。K12 样例图在本实验中是参考图，不视为经过独立逐条复核的绝对金标。

本轮只验证**有原文证据的显式先修关系**能否由 CasRel 抽取。跨句、跨章节或需要教学推理才能得到的隐含先修关系，保留在整册参考图统计中，但不把它们纳入 CasRel 的句级抽取能力判定。CasRel 的原始任务是从文本中联合抽取主体、关系和客体，能够处理同句三元组重叠；它本身不承担跨章节先修推断。参见 [CasRel 论文](https://aclanthology.org/2020.acl-main.136/)与[作者实现](https://github.com/weizhepei/CasRel)。

## 2. 最小输入与数据冻结

| 输入 | 最少保留的信息 | 用途 |
|---|---|---|
| [K12-KGraph 单册样例图](https://github.com/haolpku/K12-KGraph/blob/main/demo/kg/math_7a_rjb.json) | 上游 commit、文件 SHA-256、图谱转换规则版本 | 参考知识点和先修边 |
| 对应教材解析文本 | 版次、册次、文本 SHA-256、章节与句子位置 | 模型训练与推理输入 |
| 人工原文标注 | 标注规范、标注文件版本、训练/验证/测试章节清单 | 监督训练及原文级测试 |

先确认文本与样例图覆盖同一册、同一版次，并清理页眉、页脚和重复目录。保存 `chapter_id`、`sentence_id` 和原文字符偏移，避免分句后无法回溯证据。不得将**测试章节**的图谱节点名称、边或人工标注加入训练词典、训练样本、阈值调优或模型输入提示。

### 2.1 先做证据盘点

在正式标注前，从参考图抽查约 30～50 条 `prerequisites_for` 边，逐条查找对应教材原文，登记为：

- **显式句级**：同一句明确表达先修方向，主体与客体均可定位；适合 CasRel。
- **跨句或跨段**：需要组合多个片段；本轮不作为 CasRel 的抽取目标。
- **隐含或无可定位证据**：只在参考图中出现，或依赖教学判断；本轮不作为 CasRel 的抽取目标。

盘点不是用参考边自动生成训练标签。每条模型训练三元组仍需人工核对原文、端点跨度和方向。若显式正例很少，允许完成模型训练与推理的技术验证，但应将关系质量结论写为“样本不足”，不能据此宣称 CasRel 已能构建整册先修图。

## 3. 最小标注规范

### 3.1 知识点标注

以句子为单位标注知识点原文跨度，至少记录 `start`、`end`、`text`，采用左闭右开字符偏移。训练时转为 `B-KP`、`I-KP`、`O`，由 CRF 约束标签序列。`Concept` 和 `Skill` 在本轮合并为一个 `KP` 类，避免小样本下把类型分类也引入主要结果。

示例：

```json
{"chapter_id":"ch01","sentence_id":"s001","text":"有理数的加法遵循交换律。","entities":[{"start":0,"end":6,"text":"有理数的加法","label":"KP"},{"start":8,"end":11,"text":"交换律","label":"KP"}]}
```

上例仅示意字段和偏移格式，实际边界由标注规范与人工复核决定。遇到“有理数”和“有理数的加法”同时成立的嵌套知识点时，普通 BIO-CRF 一次只能给出一层不重叠标签；本轮预先约定优先标注教材中的完整知识点名称，并将被舍弃的嵌套项单列为方法限制。

### 3.2 显式先修三元组标注

仅当原文能支持“学习 A 是学习 B 的前提”时，标为 `(A, prerequisites_for, B)`；“A 出现在 B 之前”“A 与 B 同章”不能单独构成先修标签。记录主体和客体的原文跨度、证据句 ID、关系类型，以及 `explicit=true`。同句没有明确关系的知识点对保留为负例候选，由人工确认，不能把参考图中不存在的边自动当作负例，因为参考图可能不完整。

```json
{"chapter_id":"ch02","sentence_id":"s145","text":"掌握有理数运算是学习一元一次方程的基础。","triples":[{"subject":"有理数运算","subject_start":2,"subject_end":7,"relation":"prerequisites_for","object":"一元一次方程","object_start":10,"object_end":16,"explicit":true}]}
```

上述偏移同样只是格式示意；保存文件前须通过脚本检查 `text[start:end]` 与标注字符串一致。反向关系、仅共现、章节顺序相邻、术语相似，是优先人工检查的难负例。

### 3.3 试验规模与划分

按**章节**预先划分训练、验证、测试：选一章作为最终测试章，一章作为验证章，其余章节训练；如果教材章节过少，可按完整小节划分，但不得把相邻重叠切片分到不同集合。先从约 150～250 个句子启动知识点标注，并尽可能覆盖训练章节中明确表达先修的句子。这个量仅用于可行性试验，不是模型达到可用精度的保证；记录训练、验证、测试各自的知识点数、显式关系正例数和负例数。测试章在模型、阈值、归一规则确定前保持封存。

如果训练范围内显式先修正例不足以支持 CasRel 微调，应记录实际数量，停止对“CasRel 提升关系质量”的强结论；不能从测试章挪用正例补齐训练集。

## 4. 模型与推理流程

### 4.1 知识点识别

主模型为中文 BERT 编码器 + BiLSTM + CRF，输入分句后的教材文本，输出每个知识点的文本跨度、名称及置信信息。BERT 提供上下文表示，BiLSTM 是待验证的附加序列层，CRF 负责标签序列解码。BiLSTM+CRF 是成熟的序列标注基线，参见[原始论文](https://aclanthology.org/N16-1030/)；BERT 的预训练与微调方式参见[BERT 论文](https://aclanthology.org/N19-1423/)。

为避免把“使用了更多层”直接当成优势，最小对照先比较现有规则抽取与主模型；若需要分析 BiLSTM 的贡献，再以同一数据加做 `BERT+CRF` 消融。纯 CRF 可作为传统特征工程基线，但不是跑通本方案的前置条件。

### 4.2 显式关系抽取

中文 BERT + CasRel 直接读取原文句子，先定位主体，再针对主体预测关系和客体，输出 `(主体, prerequisites_for, 客体)` 及证据句。CasRel 不依赖上一步 CRF 先给出实体；两个模型结果在图谱组装时合并。原作者仓库记录的是较早的 Python、Keras 和 TensorFlow 环境，因此本轮把论文结构与输出格式作为依据，在当前可维护的深度学习环境中实现或选用经核验的移植实现，不把旧仓库视为直接可插入 GraphNexus 的组件。

只处理可容纳主体、客体和证据的句子；过长句的截断必须记录。若主体或客体未被知识点模型识别，可把 CasRel 的端点补为候选节点，但必须保留其来源，便于分析“关系模型补点”和“关系模型误报”。

### 4.3 图谱组装与现有项目衔接

先做离线 Python 推理程序，将每个原始命中保存在旁路证据文件中，再导出项目现有的 `CandidateGraph`：

| 推理结果 | GraphNexus 对象 | 规则 |
|---|---|---|
| 知识点命中 | [`CandidateTopic`](../src/main/java/com/graphnexus/application/evaluation/graph/model/CandidateTopic.java) | 稳定临时 ID；名称保留原始值；`domain=数学`；本轮不以类型准确率决策 |
| 显式先修三元组 | [`CandidateDependency`](../src/main/java/com/graphnexus/application/evaluation/graph/model/CandidateDependency.java) | `prerequisiteTempId=主体`、`topicTempId=客体`；端点 ID 必须能在候选节点中找到 |
| 全部原始候选 | [`CandidateGraph`](../src/main/java/com/graphnexus/application/evaluation/graph/model/CandidateGraph.java) | 交给现有评测器归一，保留原始重复与坏边统计 |

不要覆盖当前仍采用规则 `RuleBasedNerExtractor`、`RuleBasedRelationExtractor` 的 [`NlpGraphBuilder`](../src/main/java/com/graphnexus/application/evaluation/graph/builder/nlp/NlpGraphBuilder.java)。先使用独立离线 runner 读取模型结果和现有 `GoldDatasetLoader`，调用 [`StrictGraphEvaluator.evaluateReport`](../src/main/java/com/graphnexus/application/evaluation/graph/core/StrictGraphEvaluator.java) 完成评测。验证确有收益后，再决定是否增加新的 `GraphBuildMethod` 或服务接口。

## 5. 对照实验与评测口径

| 组别 | 知识点来源 | 先修关系来源 | 用途 |
|---|---|---|---|
| A：当前基线 | 现有规则 | 现有规则 | 当前项目在相同输入上的表现 |
| B：知识点模型 | BERT+BiLSTM+CRF | 现有规则 | 隔离知识点识别变化的影响；规则关系应基于 B 的候选点运行 |
| C：完整模型 | BERT+BiLSTM+CRF | CasRel | 测量显式三元组抽取带来的变化 |

三组固定教材文本、测试章节、分句方式、名称归一规则、参考图版本、评分器与评测范围。A/B/C 的模型配置、权重哈希、阈值、运行命令、随机种子和输出哈希分别记录。若 B 组现有规则关系提取器的输入接口与模型候选点不兼容，应先做明确的适配并在三组报告中说明；不得把接口失败记为模型召回率低。

分别报告以下指标，不用单一综合分代替：

1. **原文知识点跨度**：测试章人工标注上的严格跨度 Precision、Recall、F1；并记录完整名称/别名导致的误差。
2. **原文显式三元组**：测试章人工标注上的主体、关系、客体与方向全匹配 Precision、Recall、F1；另列主体或客体识别错误。
3. **图谱知识点**：测试范围内与 K12 参考节点严格名称匹配的 Precision、Recall、F1。
4. **图谱先修边**：两端知识点先严格匹配，再比较有向边的 Precision、Recall、F1。报告两套分母：人工确认有句级证据的边；测试范围内参考图全部可评估边。后者用于显示句级抽取路线的整体召回上限，不能单独用来判断 CasRel 是否正确实现。
5. **结构与错误清单**：候选点/边数量、去重数、悬空边、自环、反向边、无原文证据边，以及知识点和边的 FP/FN 明细。

测试章图谱范围应先固定：将参考知识点映射到教材章节；主图谱指标只评与测试章对应的节点，以及**两端均在该测试范围内**的先修边。跨测试章边另列，不擅自归为漏抽。若参考图无法可靠完成章节映射，优先完成原文级测试，并把整册图谱指标标为描述性结果；同册训练后的整册分数不能作为独立泛化成绩。

## 6. 可行性判定与交付物

本试验首先回答“是否能形成可靠闭环”，其次才回答“是否超过规则基线”：

- **技术闭环完成**：同一教材快照可重复完成标注校验、训练、推理、`CandidateGraph` 转换和现有评测器评分；无静默跳过的句子或悬空端点。
- **质量结论成立**：测试集封存、对照条件一致、显式关系样本量可报告，A/B/C 各层指标及 FP/FN 可复核。若 B 或 C 未优于基线，如实报告未观察到提升。
- **推广条件**：只有在测试章知识点质量与显式关系质量均有可解释的改善，且错误清单未显示明显的无证据先修边增加时，才考虑接入生产构图流程。单册结果仅说明册内可行性，不代表跨教材版本或学科泛化。

最少保存以下交付物：冻结输入与 SHA-256、章节划分清单、标注规范与标注 JSON、模型配置和权重版本、三组原始候选图、证据文件、分项指标报告、FP/FN 清单、人工复核记录。与[现有单册最小评测方案](./K12-KGraph单册最小评测与对照实验实施方案.md)并列保存；该方案中的提示词 A/B 实验与本文模型 A/B/C 实验属于不同变量，不应混在同一比较表中归因。
