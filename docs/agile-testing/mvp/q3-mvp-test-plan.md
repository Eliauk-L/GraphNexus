## 探索/验收场景

### TC-Q3-01 · 管理员端到端 UAT — 三阶段数据链路验收

| 维度 | 说明 |
|------|------|
| **覆盖任务** | 1.1 + 1.2 + 1.3 + 2.1 + 2.2 + 3.2 |
| **测试类型** | 用户验收测试（UAT Walkthrough） |
| **执行角色** | 管理员（真实代表用户） |
| **时间盒** | 60 分钟 |

**验收任务**：

```
步骤1: PDF上传与图谱构建（阶段1.1 + 1.3）
  · 管理员上传1份真实教辅PDF（10-20页）
  · 观察：上传交互是否流畅？处理进度是否可见？
  · 验收点：处理完成后能否直观看到抽取了哪些知识点和关系？
  · 验收点：处理失败（如故意上传扫描版PDF）的错误提示是否可理解？

步骤2: CSV成绩导入（阶段1.2 + 1.3）
  · 管理员上传1份模拟成绩CSV（≥10行，含正常和异常数据）
  · 观察：CSV格式错误时的提示是否明确？
  · 验收点：导入摘要中"成功/失败/异常"三类数据的展示是否清晰？
  · 验收点：学号不存在时，冲突处理选项（跳过/自动创建）是否易懂？

步骤3: 实体对齐与宽图谱构建（阶段2.1 + 2.2）
  · 系统自动生成候选匹配对后，管理员逐条审核
  · 观察：并排对比两个实体的信息布局是否直观？
  · 验收点：批量确认操作是否有影响面预览和二次确认？
  · 验收点：合并后能否直观感知"宽图谱比之前更连通了"？

步骤4: 动态权重验证（阶段3.2）
  · 管理员模拟导入一条新的成绩数据
  · 验收点：能否在系统中直观看到权重变更前后的对比？
  · 验收点：时间衰减任务执行后，权重的批量变化是否有清晰反馈？

通过标准: 管理员独立完成全部4个步骤，无需额外指导或查阅文档
```

### TC-Q3-02 · 教师端 UAT — 归因分析核心价值验收

| 维度 | 说明 |
|------|------|
| **覆盖任务** | 3.1（核心价值交付） |
| **测试类型** | 用户验收测试（UAT） + 理解度评估 |
| **执行角色** | 教师（真实学科教师代表） |
| **时间盒** | 45 分钟 |

**验收任务**：

```
步骤1: 首次归因查询
  · 教师使用自然语言输入查询"张三 为什么二次函数薄弱"
  · 观察：输入框是否支持口语化表述？自动补全是否辅助快速选择？
  · 验收点：归因报告在15秒内返回
  · 记录：教师首次看到报告的直觉反应

步骤2: 归因报告理解度评估
  · 教师阅读归因报告3分钟后，回答以下问题：
    Q1: "张三二次函数薄弱的根本原因是什么？"（验证准确性感知）
    Q2: "报告中有哪些证据支持这个结论？"（验证证据链可理解性）
    Q3: "看完报告后，你知道接下来该怎么做吗？"（验证可操作性）
  · 通过标准: 3问全对 / ≥2问正确且余下1问偏差不大

步骤3: 交互式追问体验
  · 教师点击报告中任意根因节点进行下钻追问
  · 观察：下钻报告的因果链是否清晰？
  · 验收点：下钻操作直观（点击即可），新报告在10秒内返回

步骤4: 整体感受访谈
  · "相比于你自己分析学生成绩，这个系统有帮助吗？"
  · "有没有什么让你困惑或觉得不准确的地方？"
  · "你愿意在日常教学中使用它吗？"

通过标准: 教师能独立完成首次查询并正确理解归因报告核心结论；
         回答"愿意在日常使用"（打分≥4/5）
```

### TC-Q3-03 · LLM 归因报告质量评审 + 可用性启发式评估

| 维度 | 说明 |
|------|------|
| **覆盖任务** | 3.1（LLM输出质量） + 全流程体验 |
| **测试类型** | 专家评审（领域专家+可用性评估者） |
| **执行角色** | 教研组长 + 1名独立可用性评估者 |
| **时间盒** | 90 分钟 |

**Part A — LLM 归因报告质量评审**：

准备 3 份不同学生的归因报告（强/中/弱三种掌握程度），由教研组长逐份评分：

| 评审维度 | 评分标准 | 权重 |
|---------|---------|:--:|
| 准确性 | 归因结论与学生真实学习数据吻合度 | 30% |
| 完整性 | 是否覆盖所有显著薄弱点及前置依赖链 | 20% |
| 证据充分性 | 每条根因是否有权重+得分+时间趋势支撑 | 20% |
| 可操作性 | 教师能否直接据此制定辅导计划 | 15% |
| 可读性 | 非技术背景教师能否独立理解 | 10% |
| 无幻觉 | 报告中的数据和引用是否真实存在 | 5% |

> 通过标准：3 份报告平均分 ≥ 3.5/5.0

**Part B — 可用性启发式评估（Nielsen 简化版）**：

评估者独立检查系统，记录违反以下 5 条核心启发式原则的问题：

| # | 启发式原则 | 检查重点（GraphNexus 场景） |
|---|-----------|--------------------------|
| H1 | 系统状态可见性 | PDF 处理/LLM 分析是否有进度反馈？ |
| H3 | 用户控制与自由 | 实体合并后能否撤销？CSV 导入失败能否回滚？ |
| H5 | 错误预防 | 批量操作前是否有二次确认？ |
| H6 | 识别而非回忆 | 查询时学生姓名/知识点是否支持搜索自动补全？ |
| H9 | 帮助识别和恢复错误 | 报错信息是否提示具体原因和解决建议？ |

> 通过标准：无 P0/P1 严重可用性问题

### TC-Q3-04 · 数据质量与隐私边界探索性测试

| 维度 | 说明 |
|------|------|
| **覆盖任务** | 1.1 + 1.2 + 2.1 + 2.2 + 3.1 + 3.2（跨阶段数据质量） |
| **测试类型** | 探索性测试（Session-Based） |
| **执行角色** | 测试工程师（自由探索） |
| **时间盒** | 60 分钟 |

**Charter 描述**：

```
探索区域: 跨阶段数据质量 + 隐私边界
测试思路:
  ┌─ 数据"脏"输入 ─────────────────────────────────────┐
  │ · PDF: 上传Word另存为PDF的文件、含乱码中文的PDF       │
  │ · CSV: BOM头编码、字段含换行符、空文件、仅表头无数据   │
  │ · 观察系统如何应对——优雅降级还是直接崩溃？           │
  └────────────────────────────────────────────────────┘
  
  ┌─ 实体对齐边界 ──────────────────────────────────────┐
  │ · 3个来源出现同一知识点的3种写法，对齐逻辑是否健壮？  │
  │ · 故意合并两个明显不同的知识点，系统是否允许？       │
  │ · 合并后立即归因查询，数据一致性是否保持？           │
  └────────────────────────────────────────────────────┘
  
  ┌─ 权重更新边界 ──────────────────────────────────────┐
  │ · 权重被推到0.0或1.0后继续触发同方向更新，是否截断？ │
  │ · 同一秒内时间衰减和行为事件同时触发，结果是否确定？ │
  └────────────────────────────────────────────────────┘
  
  ┌─ 隐私边界渗透 ──────────────────────────────────────┐
  │ · 尝试通过URL篡改查看其他学生数据                    │
  │ · 尝试通过API直接调用越权访问                        │
  │ · 归因报告中是否暴露了其他学生的对比数据？           │
  └────────────────────────────────────────────────────┘

交付物: Session Report（覆盖区域+发现+建议），重点记录：
  · BUG: 任何导致数据丢失/崩溃/错误结果的问题
  · OBS: 输入边界的行为观察
  · QST: 对业务逻辑合理性的疑问
```
