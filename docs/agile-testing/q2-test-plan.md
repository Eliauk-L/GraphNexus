### 2.2 Q2 vs Q1 的区别

| 维度 | Q1（技术面） | Q2（业务面） |
|------|------------|------------|
| **测试语言** | 技术术语（类名、方法名） | 业务术语（用户操作、期望结果） |
| **组织方式** | 按模块/类 | 按 User Story / 功能 |
| **读者** | 开发人员 | 开发 + 产品 + 业务 |
| **关注点** | 算法正确性 | 业务流程正确性 |
| **数据** | Mock 技术数据 | 真实业务场景数据 |
| **断言** | 返回值/异常 | 业务结果/状态变化 |

### 2.3 工具链选型

| 工具 | 用途 | 适用层级 |
|------|------|---------|
| **Cucumber + Gherkin** | BDD 场景定义与执行 | MVP 6 个 Story 的验收场景 |
| **REST Assured** | API 业务场景测试 | 17 个 REST 端点的业务验证 |
| **Testcontainers (Neo4j)** | 业务数据环境 | 需要真实图谱数据的场景 |
| **Awaitility** | 异步处理等待 | PDF 上传异步处理、消息队列消费 |
| **Allure / Cucumber Reports** | 活文档报告 | 生成业务可读的测试报告 |

### 3.1 Story 1 — 教辅 PDF 上传与图谱构建

```gherkin
Feature: Story 1 — 教辅 PDF 上传与图谱构建
  作为 管理员
  我希望 上传教辅 PDF 文件并自动构建知识图谱
  以便 将教辅资料结构化入库，为后续分析提供数据基础

  Background:
    Given 管理员已登录系统
    And 系统中已存在学科分类"数学"

  @smoke @story-1 @happy-path
  Scenario: S1-01 成功上传并处理一份教辅 PDF
    Given 管理员选择学科分类"数学"
    When 管理员上传一份 15 页的 PDF 文件"中考数学二次函数.pdf"
    Then 系统返回 202 Accepted，包含 taskId
    And 在 60 秒内，Document 状态变为 "COMPLETED"
    And 处理摘要包含：
      | 指标         | 期望         |
      | 抽取实体数   | > 0         |
      | 关系数       | > 0         |
      | 处理耗时     | < 60 秒      |
    And 知识点节点已写入 Neo4j
    And 知识点与文档之间已建立 EXTRACTION 关系边
    And 管理员收到"PDF 解析完成"通知

  @story-1 @validation
  Scenario: S1-02 上传非 PDF 格式文件被拒绝
    When 管理员尝试上传一个 .docx 文件"教辅资料.docx"
    Then 系统返回 400 Bad Request
    And 错误消息包含"仅支持 PDF 格式"

  @story-1 @validation
  Scenario: S1-03 上传超大文件被拒绝
    When 管理员尝试上传一个超过大小限制的 PDF 文件
    Then 系统返回 413 Payload Too Large
    And 错误消息提示文件大小限制

  @story-1 @error-handling
  Scenario: S1-04 扫描版 PDF 无 OCR 层处理失败
    Given 管理员上传一份扫描版图片 PDF"扫描教辅.pdf"
    When PDF 解析流水线检测到无文本层
    Then Document 状态变为 "FAILED"
    And 失败原因记录为 "该 PDF 可能为扫描图片，请提供文本版"
    And 管理员收到解析失败通知

  @story-1 @error-handling
  Scenario: S1-05 NER 提取实体为空但不中断流水线
    Given 管理员上传一份文本内容极简的 PDF
    When 版面分析成功但 NER 抽取实体数为 0
    Then Document 状态变为 "COMPLETED_WITH_WARNING"
    And 处理摘要提示"未识别到知识点"
    And 低置信度实体列表为空

  @story-1 @edge-case
  Scenario: S1-06 上传已加密的 PDF
    When 管理员上传一份受密码保护的加密 PDF
    Then 系统返回 400 Bad Request
    And 错误消息提示"不支持加密 PDF，请解密后重新上传"

  @story-1 @data-integrity
  Scenario: S1-07 知识点抽取结果包含置信度分布
    Given 管理员上传一份包含多个概念的 PDF
    When 处理完成后
    Then 处理摘要包含置信度分布：
      | 置信度档位 | 期望       |
      | 高 (>0.8)  | 有实体     |
      | 中 (0.5-0.8) | 有实体   |
    And 低置信度（<0.5）实体列表推送至实体对齐候选池
```

### 3.2 Story 2 — 学生主数据维护与成绩导入

```gherkin
Feature: Story 2 — 学生主数据维护与成绩导入
  作为 管理员
  我希望 维护学生信息并导入考试成绩 CSV
  以便 学生作为宽图谱的"图钉"节点，成绩事件化入库

  Background:
    Given 管理员已登录系统
    And 班级"初三(2)班"已创建
    And 知识体系中有知识点"二次函数"(KP-MATH-042)

  @smoke @story-2 @happy-path
  Scenario: S2-01 新增学生并导入成绩 CSV
    Given 管理员新增学生：
      | 姓名 | 学号      | 班级     |
      | 张三 | STU-001  | 初三(2)班 |
    When 管理员上传成绩 CSV 文件"月考成绩.csv"，内容为：
      | 学号     | 科目 | 知识点     | 得分 | 满分 |
      | STU-001 | 数学 | 二次函数   | 45  | 100 |
      | STU-001 | 数学 | 一元一次方程 | 90  | 100 |
    Then 导入摘要显示：成功 2 条，失败 0 条
    And 生成 2 个 ExamEvent 节点
    And ExamEvent 节点关联学生 STU-001
    And ExamEvent 节点关联对应知识点
    And 触发权重更新：STU-001 → 二次函数 权重降低

  @story-2 @validation
  Scenario: S2-02 CSV 缺少必填字段被拒绝
    When 管理员上传缺少"学号"字段的 CSV 文件
    Then 系统返回 400 Bad Request
    And 错误消息列出缺失字段"学号"

  @story-2 @conflict-resolution
  Scenario: S2-03 CSV 中学号不存在时的冲突处理（跳过模式）
    Given 冲突处理策略设置为"标记为异常跳过"
    When 管理员上传包含不存在的学号"STU-999"的 CSV
    Then 该行标记为"异常-学号不存在"
    And 导入摘要显示：成功 N 条，失败 1 条
    And 异常明细包含 "STU-999：学号不存在"

  @story-2 @conflict-resolution
  Scenario: S2-04 CSV 中学号不存在时的冲突处理（自动创建模式）
    Given 冲突处理策略设置为"自动创建学生节点"
    When 管理员上传包含不存在的学号"STU-999"的 CSV
    Then 自动创建 Student 节点（学号=STU-999，姓名为占位值）
    And 导入摘要显示：成功（含自动创建 1 名学生）

  @story-2 @validation
  Scenario: S2-05 CSV 中得分超出合法范围
    Given CSV 中一行数据得分为 120（满分 100）
    When 管理员上传该 CSV
    Then 该行标记为"异常-得分超出合法范围"
    And 不影响其他行的正常导入

  @story-2 @business-rule
  Scenario: S2-06 知识点名称无法匹配时标记待确认
    Given CSV 中包含知识点"因式分解法"，但知识体系中不存在
    When 管理员上传该 CSV
    Then 该行的知识点标记为"待确认"
    And 事件节点暂存不入库
    And 生成实体对齐候选对（CSV"因式分解法"↔ 待匹配）

  @story-2 @data-integrity
  Scenario: S2-07 同一学生同一知识点多次导入权重累积生效
    Given STU-001 对"二次函数"的当前权重为 0.5
    When 连续导入两次"二次函数"成绩：得分 0（错误）和 得分 100（正确）
    Then 权重按行为规则顺序更新两次
    And WeightChangeLog 记录两条变更记录
```

### 3.3 Story 3 — 实体对齐审核与管理

```gherkin
Feature: Story 3 — 实体对齐审核与管理
  作为 管理员
  我希望 审核和管理系统自动识别的疑似重复实体
  以便 在自动化效率与数据准确性之间取得平衡

  Background:
    Given 管理员已登录系统
    And PDF 解析抽取了知识点"二次函数"
    And CSV 导入引入了知识点"一元二次函数"
    And 系统已自动生成候选匹配对（置信度 0.85）

  @smoke @story-3 @happy-path
  Scenario: S3-01 逐条审核并确认合并
    Given 管理员查看实体对齐候选列表
    When 管理员打开"二次函数"↔"一元二次函数"的审核详情
    Then 系统并排展示两个实体的完整信息：
      | 信息项     | 实体A"二次函数"    | 实体B"一元二次函数" |
      | 来源       | PDF《中考数学》     | CSV 月考成绩        |
      | 关联关系数 | 3                  | 2                  |
    When 管理员确认合并，选择保留主实体"二次函数"
    Then 系统执行合并操作：
      And 实体B"一元二次函数"的 2 条关系迁移至实体A
      And 实体B"一元二次函数"被删除
      And 宽图谱中仅存在"二次函数"节点
    And 操作影响面回显：{合并对数:1, 影响关系数:2}

  @story-3 @business-rule
  Scenario: S3-02 驳回候选匹配对
    Given 管理员查看候选匹配对"一次函数"↔"反比例函数"（置信度 0.55）
    When 管理员判定二者为不同实体，点击"驳回"
    Then 该匹配对状态变为"REJECTED"
    And 系统不再建议合并这两个实体

  @story-3 @batch-operation
  Scenario: S3-03 按置信度区间批量确认合并
    Given 系统中有 15 对高置信度（>0.9）的候选匹配对
    When 管理员选择"批量确认所有高置信度匹配对"
    Then 操作前展示影响面摘要：
      | 将合并对数 | 15     |
      | 影响关系数 | 合计值 |
    When 管理员二次确认
    Then 15 对全部合并完成
    And 返回批量操作结果摘要

  @story-3 @business-rule
  Scenario: S3-04 低置信度候选对仅作提示
    Given 系统中有一对低置信度（0.45）的候选匹配对
    When 管理员查看该匹配对
    Then 界面标注"仅供参考"
    And 不提供批量操作中的自动确认选项

  @story-3 @data-integrity
  Scenario: S3-05 合并后数据一致性验证
    Given 实体A有关联关系 [R1, R2]，实体B有关联关系 [R3, R4]
    When 确认将 B 合并至 A
    Then A 的关联关系变为 [R1, R2, R3, R4]
    And B 从 Neo4j 中删除
    And 宽图谱的总关系数 = 原总数（不变，因为关系迁移而非删除）
```

### 3.5 Story 5 — 单学生薄弱点归因查询

```gherkin
Feature: Story 5 — 单学生薄弱点归因查询
  作为 教师
  我希望 查询学生薄弱知识点的根本原因
  以便 实施精准辅导

  Background:
    Given 教师已登录系统
    And 教师任教班级为"初三(2)班"
    And 学生"张三"(STU-001)在初三(2)班
    And 宽图谱已融合（含学生节点、知识点节点、事件节点、前置依赖边）
    And 剪枝策略已配置（归因分析：maxHops=3, maxNeighbors=5, weightThreshold=0.3）
    And LLM 服务可用

  @smoke @story-5 @happy-path @core-value
  Scenario: S5-01 自然语言查询归因分析
    When 教师输入自然语言查询："张三 为什么二次函数薄弱"
    Then 系统进行意图识别，路由到"归因分析"任务
    And 剪枝引擎从宽图谱提取子图
    And 子图中包含张三→二次函数 的 MASTERY 边及前置依赖链
    And LLM 返回结构化的归因报告，包含：
      | 报告组成       | 说明                        |
      | 薄弱根因列表   | 按影响程度降序，≥ 1 项       |
      | 多维证据链     | 前置知识权重 + 考试得分 + 时间趋势 |
      | 原文引用       | 如"第3次月考第8题得分 0"      |
      | 置信度标注     | 每项根因标注高/中/低          |
    And 端到端响应时间 < 15 秒

  @story-5 @input-mode
  Scenario: S5-02 结构化选择查询
    When 教师在下拉框中选择学生"张三"
    And 检索并选择知识点"二次函数"
    And 点击"开始分析"
    Then 系统返回与 S5-01 相同结构的归因报告

  @story-5 @permission
  Scenario: S5-03 教师无权查看非任教班级学生
    Given 学生"李四"(STU-099)不在初三(2)班
    When 教师查询"李四 为什么二次函数薄弱"
    Then 系统返回 403 Forbidden
    And 不暴露学生李四的任何数据

  @story-5 @edge-case
  Scenario: S5-04 目标学生无足够分析数据
    Given 学生"王五"(STU-003)为新转入学生，仅有 1 次考试记录
    When 教师查询"王五 为什么几何薄弱"
    Then 剪枝子图仅包含基本节点，证据链不完整
    And 系统返回归因报告并提示"该学生分析数据有限，结论仅供参考"

  @story-5 @drill-down
  Scenario: S5-05 交互式追问下钻
    Given 教师已获得张三的归因报告，其中根因1为"前置知识'一元二次方程'掌握不足"
    When 教师在报告中点击根因1的"下钻分析"按钮

### 8.1 CI 流水线中的 Q2 定位

```
Git Push
  │
  ▼

├──────────────────────────────────────────┤

│  ─────────────────────────               │

│  · API 业务场景测试                        │

### 8.2 Gherkin 标签体系

| 标签 | 含义 | 运行时机 |
|------|------|---------|
| `@smoke` | 冒烟测试 | 每次 Push |
| `@happy-path` | 正常路径 | 每次 Push |
| `@story-1` ~ `@story-6` | 按 Story 分组 | Feature 分支 |
| `@validation` | 输入校验 | Feature 分支 |
| `@error-handling` | 异常处理 | Feature 分支 |
| `@permission` | 权限校验 | Feature 分支 |
| `@business-rule` | 业务规则 | PR |
| `@edge-case` | 边界场景 | PR |
| `@data-integrity` | 数据完整性 | PR |
| `@integration` | 跨模块集成 | PR |
