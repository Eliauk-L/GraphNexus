```
        面向业务（Business Facing）
                │
    Q2 ┌────────┼────────┐ Q3

                │

| 维度 | Q4 说明 |
|------|--------|
| **核心问题** | "能扛住吗？"、"安全吗？"、"可靠吗？"、"兼容吗？" |
| **执行方式** | **自动化为主**，压测工具 + 安全扫描 + 混沌工程 |
| **目标** | 保障非功能质量（性能、安全、可靠性、兼容性），代码写对≠系统能扛住真实负载 |
| **为什么越晚代价越大** | 性能瓶颈和安全漏洞发现越晚，修复代价呈指数增长。应在每个迭代中纳入非功能测试 |

## 三、性能测试

### 3.1 性能测试目标矩阵

> 基于 [physical-view.md](physical-view.md) 中定义的节点规格和 [use-case-view.md](use-case-view.md) 中的性能要求。

| 测试类型 | 目标 | 执行频率 | 环境要求 |
|---------|------|---------|---------|
| **负载测试** | 验证系统在预期负载下的表现 | 每个迭代 | 类生产环境（等比例缩小的 K8s） |
| **压力测试** | 找到系统极限拐点 | 每个大版本 | 类生产环境 |
| **尖峰测试** | 验证突发流量下的弹性 | 每个大版本 | 类生产环境 + HPA 开启 |
| **耐久性测试** | 发现内存泄漏、连接池耗尽 | 里程碑节点 | 类生产环境（长时间运行） |
| **各层专项** | 逐层验证性能指标 | 每个迭代 | 可控测试环境 |

```

         5min  5min  5min  5min  5min   5min

### 4.3 GraphNexus 专属安全测试

#### 4.3.1 Neo4j Cypher 注入专项

> GraphNexus 大量使用动态 Cypher 查询，是最高风险攻击面。

| 测试编号 | 注入点 | 注入 Payload | 预期防御 |
|---------|--------|-------------|---------|
| **SEC-GDB-01** | 知识点名称搜索 | `' MATCH (s:Student) RETURN s.name--` | 返回空结果或无影响 |
| **SEC-GDB-02** | 剪枝 targetNodeId | `'; MATCH (n) DETACH DELETE n;--` | 参数化查询阻止注入 |
