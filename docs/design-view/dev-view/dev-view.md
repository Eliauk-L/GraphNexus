## 二、各层详解

### 2.1 用户层

用户层分为 **两个入口**，对应不同的使用场景与通道：

#### 业务入口

面向系统的核心业务用户，通过统一业务网关访问图谱构建、智能分析、问答等核心功能。

| 组件 | 说明 |
|:--|:--|
| **管理员** | 系统管理，包括数据入库、图谱治理、基础数据配置 |
| **教师** | 教学场景，包括归因分析、班级概览、图谱可视化、报表导出 |
| **学生** | 学习场景，包括薄弱自查、复习推荐、进度追踪 |

#### 运维入口

面向系统运维与运营人员，通过独立运维通道管理系统健康、监控、配置与分析统计。

| 组件 | 说明 |
|:--|:--|
| **运维人员** | 系统运维，包括健康监控、告警配置、日志查询、备份恢复、定时任务 |
| **运营人员** | 运营分析，包括使用量统计、文档处理量统计、LLM 配置管理 |

> 两个入口的用户在网关层统一通过认证鉴权后，各自访问对应的应用层模块。

### 2.2 网关层

| 组件 | 职责 |
|:--|:--|
| **认证** | JWT Token 签发与校验，用户身份验证 |
| **鉴权** | 基于角色的访问控制（RBAC），数据范围隔离（DataScope） |

> 网关层是用户层到应用层的唯一入口，所有请求经过认证→鉴权→转发。

### 2.3 应用层

应用层按业务能力划分为 **4 个处理模块 + 1 个基础数据模块 + 1 个 LLM 网关**：

#### 2.3.1 文档处理

核心的数据入口模块，负责将外部文档转化为系统可处理的结构化数据。

| 子模块 | 功能 |
|:--|:--|
| 文档上传 | PDF 文件上传、格式校验、存储 |
| 文档解析 | 版面分析、实体抽取、关系抽取 |
| 文档管理 | 文档生命周期管理、状态追踪、检索 |
| 数据源管理 | 成绩 CSV 导入、数据源注册与配置 |

#### 2.3.2 图处理

图谱的核心操作模块，负责图谱的构建与维护。

| 子模块 | 功能 |
|:--|:--|
| 图构建 | 从解析结果构建知识图谱节点与关系 |
| 图查询 | 图谱遍历、路径查询、子图检索 |
| 图管理 | 图谱版本管理、快照、全局拓扑浏览 |
| 边权更新 | 基于时间衰减和行为反馈的权重动态调整 |

#### 2.3.3 图分析

图谱的高级分析模块，提供结构化数据的深度挖掘能力。

| 子模块 | 功能 |
|:--|:--|
| 图融合 | 多源图谱融合、宽图谱构建 |
| 图剪枝 | 子图提取、策略驱动剪枝、上下文范围控制 |
| 图谱度量 | 社区发现、连通分量、图谱健康指标计算 |
| 实体对齐 | 跨文档实体匹配、合并审核、对齐回滚 |

#### 2.3.4 智能查询

面向最终用户的核心交互出口，将图谱分析结果转化为可理解的答案和建议。

| 子模块 | 功能 |
|:--|:--|
| 上下文组装 | 剪枝子图 → 结构化 Context → Prompt 构造 |
| 智能对话 | Chat 问答、归因问答、链式追问 |
| 配置管理 | Prompt 模板、模型选择、配额策略 |
| 报告导出 | 多格式报告渲染（PDF/HTML/MD）、加密分享、批量导出 |

#### 2.3.5 基础数据

位于应用层底部的共享支撑模块。

| 子模块 | 功能 |
|:--|:--|
| 用户管理 | 账号创建、状态管理、批量导入 |
| 角色管理 | 角色定义、权限分配、RBAC 矩阵 |
| 运维管理 | 健康监控、告警规则、备份恢复、定时任务管理 |
| 运营管理 | 使用量统计、文档处理统计、趋势分析 |

#### 2.3.6 LLM 网关

应用层中的虚线框模块，作为大模型调用的统一出入口。

| 子模块 | 功能 |
|:--|:--|
| **Doubao** | 豆包大模型适配器 |
| **Deepseek** | DeepSeek 大模型适配器 |
| **···** | 可扩展接入其他模型，支持模型路由与降级 |

#### 模块间依赖方向

> 与 drawio 图中虚线箭头一致：右侧模块依赖左侧模块的输出。

```
智能查询 ──▶ 图分析 ──▶ 图处理 ──▶ 文档处理
    │
    ▼
  LLM 网关
```

> 数据实际流向：文档处理 → 图处理 → 图分析 → 智能查询 → LLM 网关（从左向右），
> 依赖方向与之相反（从右向左）。

---

### 2.4 基础设施层

| 组件 | 用途 | 说明 |
|:--|:--|:--|
| **Neo4j** | 图数据库 | 知识图谱节点与关系的持久化存储，Cypher 路径查询、图算法执行 |
| **MySQL** | 关系数据库 | 结构化配置、用户权限、日志审计、任务执行记录等关系型数据 |
| **Redis** | 缓存数据库 | 热点图谱数据缓存、Session 管理、LLM 响应缓存、配额计数 |
| **MinIO** | 文件存储 | PDF 文件、解析结果、导出报告等对象存储，支持预签名 URL 分享 |
| **RabbitMQ** | 消息队列 | 领域事件异步消费（文档解析完成、权重更新、备份完成等） |

---

### 2.5 横向切面

| 模块 | 说明 | 贯穿方式 |
|:--|:--|:--|
| **日志** | 全链路日志记录，Trace ID 串联用户层→网关→应用→基础设施 | Filter + AOP 切面 |
| **备份** | 图数据库全量/增量备份，备份文件存储与完整性校验 | 定时任务 + MinIO |
| **监控** | 服务健康检查、性能指标采集、多级告警（P0/P1/P2） | Actuator + 定时采集 |
| **定时任务** | 权重衰减、图谱更新、配额重置、统计预聚合等 9 个 Quartz Job | Quartz Scheduler |

## 三、层间依赖关系

```
用户层
  │
  ├── 业务入口（管理员 / 教师 / 学生）──▶ 业务功能
  │
  └── 运维入口（运维人员 / 运营人员）──▶ 运维管理
  │
  ▼
网关层
  │  认证通过 + 鉴权通过 + 注入数据范围 → 转发请求
  ▼
应用层
  │  编排业务流程，调用领域服务，通过接口依赖基础设施
  ▼
基础设施层
  │  提供技术实现：Neo4j / MySQL / Redis / MinIO / RabbitMQ

横向切面层 ──▶ 纵向贯穿所有层（AOP / Filter / Event / @Scheduled）
```

| 依赖规则 | 说明 |
|:--|:--|
| 上层依赖下层 | 用户层→网关→应用→基础设施，单向依赖 |
| 下层不感知上层 | 基础设施层不知道谁在调用它，保持技术纯粹性 |
| 横切无层级依赖 | 横向切面通过 AOP、事件监听、拦截器等方式注入，不破坏层级隔离 |

## 四、统计摘要

| 层级 | 模块数 | 核心组件 |
|:--|:--:|:--|
| 用户层 | 5 (2入口) | 业务入口(管理员/教师/学生) + 运维入口(运维人员/运营人员) |
| 网关层 | 2 | 认证、鉴权 |
| 应用层 | 22 | 文档处理(4) + 图处理(4) + 图分析(4) + 智能查询(4) + 基础数据(4) + LLM网关(2+) |
| 基础设施层 | 5 | Neo4j、MySQL、Redis、MinIO、RabbitMQ |
| 横向切面 | 4 | 日志、备份、监控、定时任务 |
