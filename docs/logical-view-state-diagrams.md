## 一、建模范围

本文档为**生命周期复杂的核心实体**绘制状态图。选取标准：

- 具有 3 个及以上状态
- 存在明确的转换规则和触发条件
- 非法转换需要显式禁止
- 状态变化影响系统行为（如是否参与计算、是否允许操作）

**选中的实体**（按模块分组，共 11 个）：

| 模块 | 实体 | 核心关注点 |
|------|------|-----------|
| M1 | Student（学生） | 归档后不参与权重计算 |
| M3 | Document（文档） | 处理流水线状态 + 失败重试 |
| M2 | EntityAlignmentPair（实体对齐候选对） | 审核流程 + 回滚 |
| M6 | PublicApplication（公开审核申请） | 审核流程 |
| M6 | ShareLink（分享链接） | 有效期 + 访问控制 |
| M7 | ScheduledTask（定时任务） | 调度生命周期 |
| M7 | TaskExecutionRecord（任务执行记录） | 执行结果分类 |
| M7 | GraphBackup（数据库备份） | 备份 + 完整性验证 |
| M7 | Notification（通知） | 未读/已读/归档生命周期 |
| M5 | PromptTemplateVersion（Prompt模板版本） | 版本切换 + 回滚激活 |
| M4 | MasteryRelation（掌握关系） | 权重区间的语义状态 |

## 三、M3 · 文档处理状态机（Document）

### 3.1 状态图

```
                    ┌─────────┐
                    │ 管理员/  │
                    │ 教师上传  │
                    └────┬────┘
                         │ uploadDocument()
                         ▼
              ┌──────────────────────┐
              │      UPLOADED        │
              │      已上传           │
              │                      │
              │ • 文件已存储(S3)      │
              │ • 等待处理队列        │
              └──────────┬───────────┘
                         │ 消息队列消费
                         │ beginProcessing()
                         ▼
              ┌──────────────────────┐
              │     PROCESSING       │
              │     处理中            │
              │                      │
              │ • 版面分析            │
              │ • NER 实体抽取        │
              │ • RE 关系抽取         │
              │ • 图谱导入            │
              └──┬───────────────┬───┘
                 │               │
        处理成功  │               │ 处理失败
        complete()               │ fail(error)
                 │               │
                 ▼               ▼
    ┌────────────────┐   ┌────────────────┐
    │   COMPLETED    │   │    FAILED      │
    │   已完成        │   │    失败         │
    │                │   │                │
    │ • 实体已入库    │   │ • 记录失败原因  │
    │ • 关系已创建    │   │ • 通知管理员    │
    │ • 通知已发送    │   │ • 可重新上传    │
    └────────┬───────┘   └────────┬───────┘
             │                    │
             │                    │ reUpload()
             │                    │ (提供新PDF)
             │                    ▼
             │           ┌────────────────┐
             │           │  RE_UPLOADING  │
             │           │  重新处理中     │
             │           │                │
             │           │ • 删除旧图谱数据│
             │           │ • 重新进入流水线│
             │           └────────┬───────┘
             │                    │
             │                    │ (同 PROCESSING 的转换)
             │                    │
             └────────────────────┘
                   (最终都会到 COMPLETED 或 FAILED)
```

### 3.2 状态转换表

| 当前状态 | 事件/触发 | 目标状态 | 条件/约束 | 动作 |
|---------|----------|---------|----------|------|
| (初始) | uploadDocument() | UPLOADED | 文件格式合法、大小合规 | 存储文件到 S3，创建 Document 节点 |
| UPLOADED | beginProcessing() | PROCESSING | 消息队列消费 | 更新状态，启动流水线 |
| PROCESSING | complete() | COMPLETED | 所有步骤成功 | 记录 ParseResult，发送通知 |
| PROCESSING | fail(error) | FAILED | 任意步骤失败 | 记录 IngestionError，发送失败通知 |
| FAILED | reUpload(newFile) | RE_UPLOADING | — | 级联删除旧图谱数据，存储新文件 |
| RE_UPLOADING | beginProcessing() | PROCESSING | — | 重新进入流水线 |
| COMPLETED | reUpload(newFile) | RE_UPLOADING | 管理员主动操作 | 级联删除旧图谱数据 |
| COMPLETED | deleteDocument() | (删除) | — | 级联删除文档及所有图谱数据 |
| FAILED | deleteDocument() | (删除) | — | 删除文档记录 |

### 3.3 处理中的子状态（流水线步骤）

```
PROCESSING 内部子状态（顺序执行）:

  ┌──────────────┐    ┌──────────────┐    ┌──────────────┐    ┌──────────────┐
  │  LAYOUT      │───▶│  NER         │───▶│  RE          │───▶│  GRAPH_IMPORT│
  │  版面分析     │    │  实体抽取     │    │  关系抽取     │    │  图谱导入     │
  └──────┬───────┘    └──────┬───────┘    └──────┬───────┘    └──────┬───────┘
         │                   │                   │                   │
         │ 失败              │ 失败              │ 失败              │ 失败
         ▼                   ▼                   ▼                   ▼
  ┌──────────────────────────────────────────────────────────────────────┐
  │                         FAILED                                       │
  │  记录失败步骤和具体错误信息                                            │
  │  如: "Step 2 NER failed: OCR unable to recognize scanned PDF"        │
  └──────────────────────────────────────────────────────────────────────┘

任意步骤失败 → 整体 FAILED，不继续后续步骤
```

### 3.4 状态对系统行为的影响

| 状态 | 教师可浏览 | 参与图谱融合 | 知识点可检索 | 可重新上传 | 可删除 |
|------|:--:|:--:|:--:|:--:|:--:|
| UPLOADED | ❌ | ❌ | ❌ | ❌ | ✅ |
| PROCESSING | ❌ | ❌ | ❌ | ❌ | ❌ |
| COMPLETED | ✅ | ✅ | ✅ | ✅ | ✅ |
| FAILED | ⚠️ 可查看错误 | ❌ | ❌ | ✅ | ✅ |
| RE_UPLOADING | ❌ | ❌ | ❌ | ❌ | ❌ |

## 四、M2 · 实体对齐审核状态机（EntityAlignmentPair）

### 4.1 状态图

```
              ┌─────────────────────┐
              │ 系统自动检测          │
              │ 名称相似度            │
              │ + 属性重叠度          │
              │ + Embedding 余弦     │
              └──────────┬──────────┘
                         │ generateCandidate()
                         ▼
              ┌──────────────────────┐
              │      PENDING         │
              │      待审核           │
              │                      │
              │ • 等待管理员审核       │
              │ • 按置信度分三档展示   │
              │   高(>0.9) 中 低(<0.6)│
              └──┬───┬───┬───────────┘
                 │   │   │
   confirmMerge  │   │   │ rejectPair()
                 │   │   │
                 │   │   │  manualCorrection()
                 │   │   │  (修正后合并)
                 │   │   ▼
                 │   │ ┌──────────────────┐
                 │   │ │     REJECTED     │
                 │   │ │     已驳回        │
                 │   │ │                  │
                 │   │ │ • 加入白名单      │
                 │   │ │ • 不再建议合并    │
                 │   │ │ • 两个实体独立存在│
                 │   │ └──────────────────┘
                 │   │
                 ▼   │
    ┌────────────────┐│
    │    MERGED      ││
    │    已合并       ││
    │                ││
    │ • 主实体保留    ││
    │ • 副实体删除    ││
    │ • 关系已迁移    ││
    │ • 记录操作日志  ││
    └───────┬────────┘│
            │         │
            │ rollbackMerge()
            │ (发现误合并)
            ▼         │
    ┌────────────────┐│
    │  ROLLBACK_DONE ││
    │  已回滚         ││
    │                ││
    │ • 副实体已恢复  ││
    │ • 关系已还原    ││
    │ • 对齐状态回退  ││
    │   为 PENDING    ││
    └────────────────┘│
                      │
            (回滚后重新进入审核流程)
```

### 4.2 状态转换表

| 当前状态 | 事件/触发 | 目标状态 | 条件/约束 | 动作 |
|---------|----------|---------|----------|------|
| (初始) | generateCandidate() | PENDING | 相似度 > 阈值 | 创建候选对，计算置信度 |
| PENDING | confirmMerge(MERGE_PRIMARY) | MERGED | 管理员确认 | 迁移关系、删除副实体、记录日志 |
| PENDING | confirmMerge(MERGE_SECONDARY) | MERGED | 管理员确认 | 同上（保留副实体名称） |
| PENDING | confirmMerge(CUSTOM_NAME) | MERGED | 管理员输入自定义名称 | 同上 |
| PENDING | rejectPair() | REJECTED | 管理员驳回 | 加入白名单 |
| PENDING | batchConfirm(pairIds) | MERGED | 批量操作 | 逐对执行合并 |
| PENDING | batchReject(pairIds) | REJECTED | 批量操作 | 逐对加入白名单 |
| MERGED | rollbackMerge(logId) | PENDING | 发现误合并 | 恢复副实体、还原关系 |
| REJECTED | (任意) | — | **终态** | 白名单永久生效 |

### 4.3 置信度分档与审核策略

```
┌─────────────────────────────────────────────────────────────────┐
│                    置信度分档与审核策略                            │
├──────────────┬──────────────────────────────────────────────────┤
│ 高置信度      │ confidence > 0.9                                 │
│ (>0.9)       │ • 建议自动合并                                    │
│              │ • 展示供管理员抽查                                  │
│              │ • 可配置为自动执行                                  │
├──────────────┼──────────────────────────────────────────────────┤
│ 中置信度      │ 0.6 ≤ confidence ≤ 0.9                           │
│ (0.6-0.9)    │ • 需管理员逐条确认                                 │
│              │ • 默认展示区域                                     │
├──────────────┼──────────────────────────────────────────────────┤
│ 低置信度      │ confidence < 0.6                                 │
│ (<0.6)       │ • 仅作提示                                        │
│              │ • 由管理员手动判定                                  │
│              │ • 默认折叠                                         │
└──────────────┴──────────────────────────────────────────────────┘
```

```
                         ▼
              ┌──────────────────────┐

              │      待审核           │

              │ • 通知管理员审核       │
              │ • 教师可撤回          │

    ┌────────────────┐   ┌────────────────┐
    │   APPROVED     │   │   REJECTED     │

    │                │   │                │
    │ • 进入全校图谱  │   │ • 仅教师个人    │

    └────────────────┘   └────────┬───────┘
                                  │
                                  │ reapply()
                                  │ (教师修改后重新提交)
                                  ▼

                         │    (重新审核)   │
                         └────────────────┘
```

### 5.2 状态转换表

| 当前状态 | 事件/触发 | 目标状态 | 条件/约束 | 动作 |
|---------|----------|---------|----------|------|
| (初始) | applyForPublic() | PENDING | 文档在教师个人空间 | 创建申请，通知管理员 |

| PENDING | withdraw() | (删除) | 教师主动撤回 | 删除申请记录 |
| REJECTED | reapply() | PENDING | 教师修改后重新提交 | 创建新申请 |
| APPROVED | (任意) | — | **终态** | 文档已公开 |

## 六、M6 · 分享链接状态机（ShareLink）

### 6.1 状态图

```
              ┌─────────────────────┐
              │ 教师生成分享链接      │
              │ generateShareLink() │
              └──────────┬──────────┘
                         │
                         ▼
              ┌──────────────────────┐
              │      ACTIVE          │
              │      有效             │
              │                      │
              │ • 可被访问            │
              │ • 权限级别已设定       │
              │ • 有效期倒计时中       │
              └──┬───┬───────────────┘
                 │   │
    有效期到期    │   │ revoke()
    (自动)       │   │ (教师主动撤销)
                 │   │
                 ▼   ▼
    ┌────────────────────────────────┐
    │          INACTIVE              │
    │          已失效                 │
    │                                │
    │ • 访问返回"链接已失效"          │
    │ • 统计数据保留(历史访问记录)    │
    └────────────────────────────────┘

    权限级别说明:
    ┌──────────────────────────────────────────────────────┐
    │  SCHOOL_TEACHER  — 仅限本校教师（需登录验证）          │
    │  SPECIFIC_PARENT — 指定家长（需密码）                  │
    │  PUBLIC          — 公开（无需验证）                    │
    └──────────────────────────────────────────────────────┘

    访问流程:
    用户访问链接 → verifyShareAccess(linkId, userId?)
                  ├── ACTIVE + 权限匹配 → 允许访问，记录 DocumentAccessRecord
                  ├── ACTIVE + 权限不匹配 → 拒绝（"无权访问"）
                  ├── INACTIVE → 拒绝（"链接已失效"）
                  └── 密码验证失败 → 拒绝（"密码错误"）
```

### 6.2 状态转换表

| 当前状态 | 事件/触发 | 目标状态 | 条件/约束 | 动作 |
|---------|----------|---------|----------|------|
| (初始) | generateShareLink() | ACTIVE | 设置权限、有效期、密码 | 生成加密链接 |
| ACTIVE | 有效期到期 | INACTIVE | 系统自动检测 | 标记失效 |
| ACTIVE | revoke() | INACTIVE | 教师主动撤销 | 标记失效 |
| ACTIVE | 访问(权限匹配) | ACTIVE | 验证通过 | 记录 DocumentAccessRecord |
| INACTIVE | (任意) | — | **终态** | 不可恢复 |

| (初始) | updatePromptTemplate() | DRAFT | 模板内容合法 | 创建新版本，版本号自增 |
| DRAFT | activate() | ACTIVE | 运维确认 | 将同 taskType 的原 ACTIVE 标记为 DEPRECATED |
| DRAFT | 新版本 activate() | DEPRECATED | 未激活即被替代 | 跳过 ACTIVE 直接进入历史 |
| ACTIVE | 新版本 activate() | DEPRECATED | 新模板版本被激活 | 保留在版本历史中 |
| DEPRECATED | rollback() | ACTIVE | 运维选择回滚至此 | 当前 ACTIVE 变为 DEPRECATED |

### 12.3 与 LLM 调用的关系

对应 logical-view.md 3.5.2 `ILLMGatewayService` 和 class-diagrams.md 第五章 LLMGateway 类：

```
LLMGateway.callLLM()
    │
    ├── 加载 PromptTemplate (taskType)
    │   └── 选取 ACTIVE 版本（同一 taskType 仅一个）
    │
    ├── 渲染模板
    │   └── 填充变量: {{student_name}}, {{subgraph_json}}, {{task_type}} 等
    │
    ├── 调用 LLM API
    │   └── 配额检查 → 降级决策 → API 调用
    │
    └── 记录 LLMCallLog
        └── promptTemplateVersion: 记录使用的版本号
            (支持 replayCall() 失败调用重放)
```

### 13.2 跨实体状态关联

某些状态转换会**级联触发**其他实体的状态变化：

| 触发状态变化 | 级联影响 |
|-------------|---------|
| Student → GRADUATED/TRANSFERRED | 该学生所有 MasteryRelation 不再参与权重计算和归因分析 |
| Document → COMPLETED | 触发 M4 宽图谱增量融合（定时任务），新知识点进入知识体系 |
| Document → FAILED | 通知管理员（M7 Notification），不影响已有图谱 |
| EntityAlignmentPair → MERGED | 副实体的所有 MasteryRelation 重新指向主实体 |
| EntityAlignmentPair → MERGED → rollback | 恢复副实体及其关系，MasteryRelation 还原指向 |
| PublicApplication → APPROVED | 教师个人文档的 ExtractionRelation 合并到全校图谱 |
| ScheduledTask → FAILED | 下游依赖任务自动 SKIPPED |
| MasteryRelation 权重 < 0.15 | 该知识点进入学生薄弱列表，影响复习路径优先级排序 |
| ShareLink → INACTIVE | 访问请求返回"链接已失效"，访问统计数据保留 |
| Document → COMPLETED | 触发 M7 Notification（通知管理员解析完成） |
| Document → FAILED | 触发 M7 Notification（通知管理员解析失败） |
| PublicApplication → PENDING | 触发 M7 Notification（通知管理员待审核） |
| PublicApplication → APPROVED/REJECTED | 触发 M7 Notification（通知教师审核结果） |
| GraphBackup → INTEGRITY_FAILED | 触发 M7 Notification（通知运维备份完整性异常） |
| TaskExecutionRecord → FAILED | 触发 M7 Notification（通知运维任务执行失败） |
| PromptTemplateVersion → ACTIVE | 该版本成为 LLM 调用的生效模板，原 ACTIVE 变为 DEPRECATED；LLMCallLog 记录版本号 |
