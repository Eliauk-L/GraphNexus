## 一、物理视图概述

### 1.1 物理视图在 4+1 中的定位

物理视图（Physical View）回答**"系统如何在物理基础设施上运行"**的问题，关注：

| 维度 | 说明 |
|------|------|
| **部署拓扑** | 服务器节点、网络分区、防火墙、负载均衡器的物理布局 |
| **进程映射** | 软件组件（19 个代码模块）如何映射到物理节点和进程 |
| **通信机制** | 进程间通信协议（HTTP/REST、gRPC、消息队列） |
| **可伸缩性** | 水平扩展策略、自动扩缩容（HPA）、集群规模 |
| **容错与高可用** | 冗余设计、故障转移、数据备份与恢复 |
| **容量规划** | 各节点的 CPU、内存、磁盘、网络规格 |

### 1.2 设计原则

| 原则 | 说明 |
|------|------|
| **安全分层** | DMZ（公开服务）→ 应用层 → 数据层，逐层收紧安全组规则 |
| **无状态优先** | 业务服务无状态设计，会话状态下沉到 Redis，支持任意水平扩展 |
| **异步解耦** | 耗时操作（PDF 解析、LLM 调用、权重批处理）通过消息队列异步化 |
| **读写分离** | 图数据库和关系数据库均采用主从架构，读写分离提升吞吐 |
| **故障隔离** | 关键组件（Neo4j、Redis、MQ）均采用集群部署，单节点故障不影响整体服务 |
| **MVP 优先** | 物理拓扑标注 MVP 最小部署 vs 生产完整部署的差异 |

### 2.2 安全组规则

| 源区域 | 目标区域 | 允许协议/端口 | 说明 |
|--------|---------|-------------|------|
| Internet | DMZ | TCP/443 (HTTPS) | 用户浏览器访问 |
| DMZ (Nginx) | 应用服务区 | TCP/8080 (HTTP) | 反向代理转发 |
| 应用服务区 (API) | 消息中间件区 | TCP/5672 (AMQP) / TCP/9092 (Kafka) | 业务服务发消息 |
| 应用服务区 (API) | 数据服务区 | TCP/7687 (Neo4j Bolt), TCP/5432 (PG), TCP/6379 (Redis), TCP/9000 (MinIO) | 数据访问 |
| 应用服务区 (Consumer) | 数据服务区 | TCP/7687 (Neo4j Bolt), TCP/5432 (PG), TCP/6379 (Redis) | 异步消费者数据访问 |
| 应用服务区 | 运维管理区 | TCP/3100 (Loki), TCP/9090 (Prometheus) | 日志/指标上报 |
| 运维管理区 | 数据服务区 | TCP/7687, TCP/5432, TCP/6379 | 运维监控数据采集 |
| **禁止** | **全部其他** | — | 默认拒绝，最小权限原则 |

```
                         ┌─────────────┐
```

| **graphnexus-application** | K8s HPA 增加 Pod | CPU > 70% | 10 Pod |
| **graphnexus-graph-core** | K8s HPA 增加 Pod | CPU > 60% (图计算密集) | 8 Pod |

| **graphnexus-ingestion** | K8s HPA + MQ Consumer 扩展 | 消息积压 > 100 | 6 Pod |
| **Neo4j** | 增加 Read Replica | 读 QPS > 1000/节点 | 5 Replica |
| **PostgreSQL** | 增加 Read Standby | 读 QPS > 2000/节点 | 3 Standby |
| **Redis** | 增加 Replica + 分片 | 内存 > 80% 或 QPS > 50000 | 按需 |
| **RabbitMQ** | 增加集群节点 | 消息积压持续增长 | 7 节点 |
| **MinIO** | 增加节点 (自动 Rebalance) | 存储 > 70% | 按需 |

| **graphnexus-ai-analysis Pod** | Pod 崩溃 | 暂缺一个副本 | K8s 自动重启 | < 30s | 0 |

| **PostgreSQL Primary** | Primary 宕机 | 写操作暂停 | Patroni/pg_autoctl 自动切换 Standby | < 30s | < 1s |

## 十、安全部署考量

### 10.1 网络安全

| 控制措施 | 实现方式 |
|---------|---------|
| **网络隔离** | VPC 内四个安全组 (DMZ/App/MQ/Data)，默认拒绝所有流量，按需开放 |
| **API 认证** | JWT Token + Refresh Token，过期时间 2h/7d |
| **API 限流** | Nginx `limit_req_zone` + 应用层 RateLimiter（Redis 计数器） |
| **SQL/注入防护** | 参数化查询 (JDBC PreparedStatement)、输入校验 (L2 InputSanitizer) |
| **CORS 控制** | Nginx + Spring CORS 配置，仅允许已知前端域名 |
| **HTTPS 强制** | HSTS 头、HTTP → HTTPS 301 重定向 |
| **密钥管理** | K8s Secret + 环境变量注入，不硬编码 |
| **DDoS 防护** | CDN 层 + WAF + Nginx 连接数限制 |

### 10.2 数据安全

| 数据分类 | 存储位置 | 加密措施 |
|---------|---------|---------|
| 用户密码 | PostgreSQL | BCrypt 哈希 |
| 学生姓名/学号 | Neo4j (节点属性) | 传输层 TLS、存储层应用加密 |
| 考试得分 | Neo4j (事件节点) | 传输层 TLS |
| 归因报告 | Neo4j + Redis 缓存 | 传输层 TLS，分享链接加密 + 密码保护 |
| PDF 教辅文件 | MinIO | 传输层 TLS、存储层 SSE (Server-Side Encryption) |
| 审计日志 | PostgreSQL + Loki | 不可变存储 (WORM)，保留 1 年 |
