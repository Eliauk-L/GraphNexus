# GraphNexus User Story 需求文档

> 基于图谱技术的 AI 上下文处理与精准问答系统
>
> 版本：v1.5 | 角色数：6 | User Story 总数：33

---

## 角色总览

| # | 角色 | 一句话定位 | 核心诉求 |
|:--|:--|:--|:--|
| **US-01** | 教师 | 价值的消费者 | 精准定位学生薄弱点，获取可行动的辅导建议 |
| **US-02** | 学生 | 数据的来源与受益者 | 了解自身学习状态与知识薄弱点 |
| **US-03** | 管理员 | 数据资产的管理者 | 高效完成教辅资料与成绩数据的入库与管理 |
| **US-04** | 运维人员 | 系统稳定性的保障者 | 保障 Neo4j/LLM/解析服务的高可用运行 |
| **US-05** | 运营人员 | 系统效果的度量者 | 量化系统使用情况与业务价值 |
| **US-06** | 审计人员 | 合规与追溯的守护者 | 确保数据访问合法、决策可追溯、系统合规 |

## US-01 · 教师（8 个 Story）

### Story 1.1 — 单学生薄弱点归因查询

| 维度 | 说明 |
|:--|:--|
| **角色** | 教师 |
| **场景** | 批改作业时发现学生A连续多次在二次函数题目上出错，想了解根本原因是什么 |
| **功能** | 输入"学生A + 二次函数"并选择任务类型（归因分析），系统自动应用该任务类型对应的预配置剪枝策略生成子图，经由 LLM 生成归因分析报告，列出薄弱根因（如"缺少配方法前置知识""相关题目正确率仅 23%"）及改进建议 |
| **目的** | 从"知道学生错了"升级为"知道学生为什么错"，实现精准辅导 |

### Story 1.2 — 班级薄弱知识点概览

| 维度 | 说明 |
|:--|:--|
| **角色** | 教师 |
| **场景** | 期中考试后，想快速了解全班学生在哪些知识点上普遍薄弱，以便调整教学计划 |
| **功能** | 选择任教班级，系统基于宽图谱中所有学生的知识点掌握权重，按薄弱程度（PageRank 反向排序）展示班级共性薄弱知识点 Top-N，支持按学科筛选 |
| **目的** | 用数据替代直觉，把有限的课堂时间投入到最需要补救的知识点上 |

### Story 1.3 — 学生个体知识图谱可视化

| 维度 | 说明 |
|:--|:--|
| **角色** | 教师 |
| **场景** | 想直观了解某个学生的完整知识结构——哪些掌握了、哪些薄弱、知识点之间的前置依赖关系 |
| **功能** | 以学生为起点，展示该生的"知识掌握图谱"：节点为知识点（颜色表示掌握程度），边为前置依赖关系，支持点击展开/折叠 |
| **目的** | 将抽象的学习状态转化为可交互的可视化图谱，降低认知门槛 |

### Story 1.4 — 学生成绩趋势追踪

| 维度 | 说明 |
|:--|:--|
| **角色** | 教师 |
| **场景** | 想了解某个学生在过去一个学期中，某一知识点掌握程度的变化趋势 |
| **功能** | 选择学生 + 知识点，系统展示该生对该知识点掌握权重的时间曲线，标注关键事件节点（如"期末考""第3次作业"） |
| **目的** | 判断薄弱是"持续性的"还是"偶发性的"，辅助制定差异化辅导策略 |

### Story 1.5 — 跨学科关联分析

| 维度 | 说明 |
|:--|:--|
| **角色** | 教师 |
| **场景** | 发现学生数学成绩下滑，想确认是否与其他学科（如物理）存在关联——例如物理中大量使用二次函数 |
| **功能** | 选择学生，系统基于宽图谱展示跨学科知识点关联路径，如"物理-运动学 ← 数学-二次函数"，并标注关联强度 |
| **目的** | 突破单科视角，发现跨学科知识的相互影响，定位"假性薄弱"（数学不差，是物理场景不会用） |

### Story 1.6 — 教辅资料知识结构浏览

| 维度 | 说明 |
|:--|:--|
| **角色** | 教师 |
| **场景** | 拿到一份新的教辅 PDF，想快速了解它覆盖了哪些知识点、知识结构是怎样的，是否适合用于备课 |
| **功能** | 上传教辅 PDF 后，系统展示该文档的知识图谱：核心概念节点、公式节点、它们之间的关系网络，并标注 PageRank 最高的核心知识点 |
| **目的** | 将静态的 PDF 转化为结构化的知识网络，辅助教材选用和备课决策 |

### Story 1.7 — 教学建议生成

| 维度 | 说明 |
|:--|:--|
| **角色** | 教师 |
| **场景** | 定位到学生薄弱点后，不知道应该用什么教学策略来补救 |
| **功能** | 基于薄弱知识点的前置依赖图谱，系统生成分步补救路径："建议优先复习 X → 再讲解 Y → 配套练习 Z"，并推荐教辅资料中相关的例题页码 |
| **目的** | 从"知道问题"到"知道怎么做"，打通分析到行动的最后一公里 |

### Story 1.8 — 归因报告导出与分享

| 维度 | 说明 |
|:--|:--|
| **角色** | 教师 |
| **场景** | 家长会或教研讨论时，需要将学生的归因分析结果以可读的形式展示或分享 |
| **功能** | 将归因分析报告（含图谱可视化截图、关键数据、改进建议）导出为 PDF 或生成分享链接，支持设置访问权限 |
| **目的** | 让分析结果在教师-家长-教研组之间流动，发挥协作价值 |

## US-02 · 学生（3 个 Story）

### Story 2.1 — 个人薄弱点自助查询

| 维度 | 说明 |
|:--|:--|
| **角色** | 学生 |
| **场景** | 想自己知道自己在哪些知识点上需要加强，而不是被动等待教师告知 |
| **功能** | 学生登录后查看自己的"知识掌握仪表盘"：薄弱知识点列表、每个知识点的掌握评分、与班级平均水平的对比 |
| **目的** | 赋予学生自主学习意识，从"被分析"变为"主动了解自己" |

### Story 2.2 — 个性化复习路径推荐

| 维度 | 说明 |
|:--|:--|
| **角色** | 学生 |
| **场景** | 临近考试，时间有限，不知道应该优先复习什么 |
| **功能** | 系统基于学生薄弱知识点图谱，结合知识点的重要度（PageRank）和前置依赖关系，生成个性化的复习优先级排序："最应该先复习的 5 个知识点" |
| **目的** | 用有限复习时间撬动最大提分效果，避免盲目刷题 |

### Story 2.3 — 学习进度追踪与自我对比

| 维度 | 说明 |
|:--|:--|
| **角色** | 学生 |
| **场景** | 经过一段时间努力，想确认自己是否真的有进步 |
| **功能** | 展示学生各知识点掌握权重的历史变化曲线，标注每次考试/测验的时间节点，直观展示"进步中的知识点"和"仍需加强的知识点" |
| **目的** | 用可量化的进步反馈维持学习动力，避免"学了但感觉没进步"的挫败感 |

## US-03 · 管理员（8 个 Story）

### Story 3.1 — 教辅 PDF 上传与图谱构建

| 维度 | 说明 |
|:--|:--|
| **角色** | 管理员 |
| **场景** | 学校采购了新的教辅资料，需要将其导入系统供教师使用 |
| **功能** | 上传 PDF 文件 → 系统自动执行版面分析 → NER/RE 抽取实体与关系 → 构建文档知识图谱并导入 Neo4j → 返回构建结果摘要（抽取实体数、关系数、耗时） |
| **目的** | 将 PDF 入库流程自动化，管理员只需"上传 + 确认"，无需理解底层图谱技术 |

### Story 3.2 — 学生主数据维护与成绩导入

| 维度 | 说明 |
|:--|:--|
| **角色** | 管理员 |
| **场景** | 学期初有新学生入学或班级调整，学期中有学生转学/休学，每次考试后教务处提供全年级成绩表——学生作为宽图谱的核心"图钉"节点，其主数据的准确性直接影响图谱质量 |
| **功能** | **（1）学生主数据维护**：支持学生信息的新增（姓名、学号、班级、入学年份）、批量更新（如分班调整后批量修改班级字段）、状态标记（在读/休学/转学/毕业），离校学生数据保留但标记为归档状态，不再参与权重计算；**（2）成绩 CSV 导入与事件化**：上传 CSV 文件 → 系统校验字段格式（学号、科目、知识点、得分等）→ 将每行记录转化为事件节点并自动关联已有学生与知识点 → 返回导入结果摘要（成功条数、失败条数、异常记录及原因）；**（3）导入冲突处理**：CSV 中的学号在系统中不存在时，提示管理员选择"自动创建学生节点"或"标记为异常跳过" |
| **目的** | 将学生从"CSV 中的一行数据"提升为可主动维护的主数据实体，保障这一"图钉"节点的数据完整性和生命周期管理，同时保留批量导入的零代码效率 |

### Story 3.3 — 实体对齐审核与管理

| 维度 | 说明 |
|:--|:--|
| **角色** | 管理员 |
| **场景** | 不同来源的数据中，同一个知识点可能有不同的表述（如"二次函数" vs "一元二次函数"），系统自动合并后需要人工确认 |
| **功能** | 展示系统自动对齐的实体匹配对（含相似度分数），管理员逐一确认/驳回/手动修正，支持按置信度筛选（如"只展示 0.6-0.9 的中置信度匹配"） |
| **目的** | 在自动化效率与数据准确性之间取得平衡，关键合并不交给黑盒 |

### Story 3.4 — 数据资产总览与管理

| 维度 | 说明 |
|:--|:--|
| **角色** | 管理员 |
| **场景** | 想了解当前系统中纳管了多少数据资产，以及各资产的健康状态 |
| **功能** | 展示数据资产仪表盘：已上传的 PDF 数量及解析状态、CSV 导入记录、图谱节点/关系总数、各资产最后更新时间、异常数据标记（如解析失败的 PDF、字段缺失的 CSV 记录） |
| **目的** | 全局掌控数据资产状态，异常数据及时处理，避免"垃圾进垃圾出" |

### Story 3.5 — 剪枝策略配置与管理

| 维度 | 说明 |
|:--|:--|
| **角色** | 管理员 |
| **场景** | 系统支持多种任务类型（归因分析、复习推荐、班级概览等），不同任务对子图的深度、广度、权重阈值要求不同——归因分析需要追溯深层前置依赖链，复习推荐则需要聚焦近期薄弱知识点。需要为每种任务类型配置和调优独立的剪枝策略 |
| **功能** | **（1）策略模板管理**：为每种任务类型（归因分析 / 复习推荐 / 班级概览）配置独立的剪枝策略参数——最大跳数（深度，如归因分析 3 跳、复习推荐 2 跳）、每跳最大邻居数（广度，如每跳保留 Top-K 个最强关联邻居）、关系权重阈值（低于该值的边被剪掉，如仅保留权重 > 0.3 的掌握关系）、关系类型过滤（如归因分析保留"掌握""前置依赖""同知识点"，排除"同班同学"等弱相关关系）；**（2）策略对比测试**：选择同一查询目标，使用 A/B 两种策略分别生成子图，系统对比输出节点数、关系数、LLM Token 消耗量，辅助管理员判断策略优劣；**（3）策略版本管理**：每次修改策略自动保存历史版本，支持查看变更 Diff 和回滚到任意历史版本 |
| **目的** | 将"任务驱动剪枝"从硬编码逻辑提升为可配置、可对比、可回滚的系统策略，让不同任务使用最优剪枝参数，在子图信息完整度与 LLM Token 成本之间取得平衡 |

### Story 3.6 — 权重更新规则配置

| 维度 | 说明 |
|:--|:--|
| **角色** | 管理员 |
| **场景** | 学生与知识点的"掌握"关系权重不是静态的——随着时间推移旧成绩应自然衰减，新的考试/作业数据应及时增强或削弱权重。不同的学科和年级可能需要不同的衰减节奏（如小学数学遗忘慢、高中物理遗忘快），不能将衰减公式硬编码在代码中 |
| **功能** | **（1）时间衰减规则配置**：定义全局或按学科的衰减参数——衰减曲线类型（指数衰减 / 线性衰减 / 阶梯衰减）、半衰期（如"数学知识点 90 天不再练习则权重减半"）、衰减计算周期（如每天凌晨执行、每周一执行）；**（2）行为事件权重规则配置**：定义什么事件触发多大权重的调整——正确作答（权重 +Δ，如 +0.05）、错误作答（权重 -Δ，如 -0.08）、课堂表现优秀（权重 +Δ，如 +0.03）、长时间未接触（自动衰减，按上方规则执行），支持按事件类型分别设置调整幅度和生效范围（仅影响该知识点 / 影响所有前置依赖知识点）；**（3）规则模拟与影响预估**：选择一条配置中的规则，在指定学生/班级范围上模拟执行，系统输出将有多少条"掌握"关系权重发生变化、变化分布（增强/削弱的比例），辅助管理员评估规则变更的影响范围，避免衰减过激导致全校数据失真；**（4）权重变更日志**：每次权重更新（无论由定时任务还是事件触发）自动记录：变更时间、变更前后的权重值、触发原因（具体衰减规则 ID 或事件 ID）、操作来源（系统自动 / 管理员手动修正） |
| **目的** | 将"动态更新"支柱从硬编码脚本提升为可配置、可模拟、可追溯的业务规则引擎，让权重变化有理有据，既反映真实学习规律，又经得起审计追溯 |

### Story 3.7 — 宽图谱全局浏览

| 维度 | 说明 |
|:--|:--|
| **角色** | 管理员 |
| **场景** | 随着 PDF 教辅和成绩数据不断入库，宽图谱持续增长。管理员需要直观了解当前图谱的全局结构——哪些知识点是核心枢纽、知识结构是否合理、是否存在数据稀疏的"冷区"——而不是从统计数字中猜测图谱形态 |
| **功能** | **（1）全局拓扑概览**：以力导向布局展示宽图谱的全貌——节点为知识点/学生/事件实体，边为它们之间的关系，节点大小反映 PageRank 或度中心性，支持缩放、拖拽、按实体类型筛选显示；**（2）聚类与社区发现**：按学科、年级或自动检测的社区结构对图谱着色分组，直观展示不同学科知识点的聚集程度和跨学科桥接节点；**（3）聚焦与下钻**：点击任意节点展开其邻域子图，查看该节点的关联实体与关系权重；支持按学科/年级/实体类型一键聚焦，过滤无关节点；**（4）图谱健康度度量**：展示全局图谱指标——节点数/关系数、平均度、连通分量数、孤立节点列表（未被任何关系连接的知识点/学生）、关系密度热力图（按学科区域显示边的稠密程度），辅助管理员识别数据盲区 |
| **目的** | 为宽图谱这一核心数据资产提供一张"活地图"——从统计数字（3.4）升级为可交互的全局可视化视图，让管理员能够发现知识结构问题（如某学科知识点之间缺乏前置依赖关系）、定位数据稀疏区域，指导后续的数据补充和实体对齐工作 |

### Story 3.8 — 知识体系管理

| 维度 | 说明 |
|:--|:--|
| **角色** | 管理员 |
| **场景** | 知识点是宽图谱的另一个核心"图钉"节点。PDF 文档解析能自动抽取知识点实体，但知识点的层级结构（如"函数 → 二次函数 → 配方法"）、学科归属、以及知识点之间的前置依赖关系（学 A 之前必须先掌握 B），需要人工定义和维护，不能完全依赖自动抽取 |
| **功能** | **（1）知识点分类树管理**：支持多级树形结构的创建与编辑——学科（数学/物理/...）→ 一级模块（代数/几何/...）→ 二级章节（函数/方程/...）→ 具体知识点（二次函数），支持拖拽调整层级、批量导入分类模板；**（2）前置依赖关系定义**：在教育学中知识点之间存在严格的学习路径依赖——如"配方法"的前置依赖是"一元二次方程"和"完全平方公式"。管理员可为任意知识点指定其前置依赖知识点，系统自动构建"知识依赖有向图"并在宽图谱中与对应实体节点关联；**（3）知识点节点管理**：查看所有知识点实体列表（含来源——自动抽取/人工创建/CSV 导入）、编辑知识点名称与描述、合并重复知识点（与 Story 3.3 实体对齐联动）、标记废弃知识点（不再纳入剪枝和权重计算）；**（4）知识体系完整性检查**：系统自动检测分类树中的空节点（有分类无知识点）、孤立知识点（未被任何分类树层级覆盖）、循环依赖（A 依赖 B、B 依赖 A），生成完整性报告 |
| **目的** | 将知识点从"被抽取的标签集合"提升为具有层级结构、学科归属和学习路径依赖的有序知识体系，让教师的归因分析（如"学生缺少配方法前置知识"）有据可依，让剪枝策略（如"沿前置依赖链上溯 2 跳"）有图可循 |

## US-04 · 运维人员（6 个 Story）

### Story 4.1 — 系统健康监控仪表盘

| 维度 | 说明 |
|:--|:--|
| **角色** | 运维人员 |
| **场景** | 日常值班时，需要一眼确认整个系统的各项服务是否正常运行 |
| **功能** | 展示核心服务健康面板：Neo4j 连接状态与查询延迟、LLM API 可用性与响应时间、PDF 解析服务状态、图谱构建任务状态。异常项高亮标红并显示持续时长 |
| **目的** | 从"用户投诉才知道出问题"变为"问题发生前或发生时立刻感知" |

### Story 4.2 — 告警规则配置与通知

| 维度 | 说明 |
|:--|:--|
| **角色** | 运维人员 |
| **场景** | 需要在关键服务异常、性能下降或任务失败时第一时间收到通知 |
| **功能** | 配置告警规则（如"LLM API 连续失败 3 次""Neo4j 查询 P99 延迟 > 5s""图谱构建任务失败"），设置通知渠道（邮件/短信/企业微信），支持告警静默时段设置 |
| **目的** | 自动化监控替代人工巡检，缩短故障发现-响应-恢复的时间窗口 |

### Story 4.3 — 系统日志查询与分析

| 维度 | 说明 |
|:--|:--|
| **角色** | 运维人员 |
| **场景** | 收到告警或用户反馈异常后，需要快速定位问题根因 |
| **功能** | 提供统一的日志搜索界面：按时间范围、服务名称、日志级别（ERROR/WARN/INFO）、关键字进行组合查询。支持上下文展开（查看错误发生前后的关联日志）和慢查询高亮 |
| **目的** | 将排障效率从"翻多台服务器的日志文件"压缩到"一个搜索框定位" |

### Story 4.4 — 图数据库备份与恢复

| 维度 | 说明 |
|:--|:--|
| **角色** | 运维人员 |
| **场景** | 防止数据丢失或因错误操作导致图谱损坏，需要定期备份并在必要时回滚 |
| **功能** | 支持 Neo4j 数据库的定时自动备份（配置备份周期与保留份数）、手动触发备份、从指定备份点一键恢复。操作前系统自动验证备份完整性 |
| **目的** | 保障图数据资产不因硬件故障、人为误操作或软件缺陷而不可恢复 |

### Story 4.5 — 定时任务管理与监控

| 维度 | 说明 |
|:--|:--|
| **角色** | 运维人员 |
| **场景** | 系统的图谱增量更新、权重时间衰减计算等任务需要在非业务高峰期定时执行 |
| **功能** | 查看所有定时任务列表（任务名、Cron 表达式、最近执行状态、耗时），支持手动触发/暂停/恢复单个任务（如"权重时间衰减计算""图谱增量更新"），任务执行失败时自动记录错误详情并触发告警 |
| **目的** | 确保关键的后台批量处理任务不遗漏、不静默失败 |

### Story 4.6 — LLM 配置管理

| 维度 | 说明 |
|:--|:--|
| **角色** | 运维人员 |
| **场景** | LLM 是系统的核心推理引擎，贯穿文档解析（NER/RE 抽取）、归因分析生成、教学建议生成等关键链路。不同任务对模型能力的要求不同——归因分析需要强推理能力的高阶模型，批量文档解析可使用成本更低的轻量模型。同时，模型 API 有调用配额和成本限制，需要可观测和可控制 |
| **功能** | **（1）模型选择与切换**：为各任务场景（文档 NER/RE 抽取 / 归因分析 / 教学建议生成 / 复习路径推荐）分别指定使用的 LLM 模型（如 Claude Opus / Sonnet / Haiku 或其他兼容 API 的模型），支持一键切换模型而不重启服务，切换时系统自动校验新模型的 API 连通性；**（2）Prompt 模板管理**：为每种任务场景维护对应的 Prompt 模板——模板支持变量占位符（如 `{{student_name}}`、`{{knowledge_point}}`、`{{subgraph_json}}`），提供模板编辑、版本历史、回滚功能，支持模板在线预览（填入测试变量值，查看渲染后的完整 Prompt）；**（3）调用配额与成本控制**：配置每个模型的日/周/月调用次数上限和 Token 消耗上限，达到阈值时自动触发降级策略（如归因分析模型降级为备用模型，或暂停非核心任务如批量文档解析），展示当前周期调用量、Token 消耗量、预估费用仪表盘；**（4）调用日志与异常追溯**：记录每次 LLM 调用的完整信息——时间、任务类型、模型名称、Prompt 模板版本、输入 Token 数、输出 Token 数、响应延迟、调用结果（成功/失败/超时），失败调用自动标记并支持重放（使用相同参数重新调用） |
| **目的** | 将 LLM 从"代码中写死的 API 调用"提升为可切换、可观测、可审计的受控基础设施，在推理质量、响应速度和调用成本之间取得可量化的平衡 |

## US-06 · 审计人员（4 个 Story）

### Story 6.1 — 数据访问行为审计

| 维度 | 说明 |
|:--|:--|
| **角色** | 审计人员 |
| **场景** | 收到投诉或定期审计时，需要追溯"谁在什么时间查看了哪个学生的什么数据" |
| **功能** | 搜索并展示数据访问日志：操作时间、操作者身份（教师/管理员/其他）、操作类型（查询/导出/下载）、目标学生 ID、返回结果摘要。支持按时间范围、操作者、目标学生多条件组合筛选，支持导出审计记录为 CSV/PDF |
| **目的** | 实现"每一次数据访问都有迹可循"，满足《个人信息保护法》对敏感个人信息处理的审计追溯要求 |

### Story 6.2 — 图谱状态快照与归因回放

| 维度 | 说明 |
|:--|:--|
| **角色** | 审计人员 |
| **场景** | 某次归因分析的结论受到质疑（如家长投诉"系统把我孩子错误标记为薄弱"），需要回放当时的决策过程 |
| **功能** | 每次归因查询自动保存当时的子图快照（剪枝前后的节点与关系）、剪枝策略参数（策略名称与版本号）、LLM 输入 Prompt 与输出结果。审计人员可通过归因记录 ID 一键回放完整的决策链 |
| **目的** | 保障 AI 归因的**可解释性与可复现性**——同一图谱状态 + 同一参数，必须产生一致的结论。系统判断不能被当作不可质疑的黑盒 |

### Story 6.3 — 数据变更追溯

| 维度 | 说明 |
|:--|:--|
| **角色** | 审计人员 |
| **场景** | 发现某学生的知识点掌握权重出现异常波动，需要追溯到是哪条数据录入或哪次更新导致的 |
| **功能** | 以"学生 + 知识点"或"学生 + 时间范围"为入口，展示该实体/关系的完整变更历史：变更时间、变更前后值、触发变更的源事件（如"第3次月考成绩导入""时间衰减规则执行""管理员手动修正"）、操作者身份（系统/管理员） |
| **目的** | 确保每一次数据变更都有明确的"责任人 + 原因"，防止数据篡改无从查证 |

### Story 6.4 — 合规规则配置与自动审查

| 维度 | 说明 |
|:--|:--|
| **角色** | 审计人员 |
| **场景** | 不希望每件事都手动查——系统应该能按预设规则自动发现和告警异常行为 |
| **功能** | 配置合规审查规则（如"教师单日查询非任教班级学生超过 N 次""单次导出学生报告超过 M 份""包含未脱敏字段的导出操作"），系统按规则自动扫描并生成"异常行为清单"，审计人员可查看详情并标记处理状态（待处理/已确认违规/已排除） |
| **目的** | 将审计模式从"被动响应投诉"升级为"主动发现风险"，降低合规事故概率 |

## 优先级建议

### P0 — 核心功能（MVP，第一阶段交付）

| Story | 理由 |
|:--|:--|
| **1.1** 单学生薄弱点归因查询 | 系统的核心价值主张，没有它系统不成立（MVP 阶段使用默认剪枝策略） |
| **3.1** PDF 上传与图谱构建 | 图谱数据的入口，1.1 的前置依赖 |
| **3.2** 学生主数据维护与成绩导入 | 学生"图钉"节点的入口，1.1 的前置依赖 |
| **4.1** 系统健康监控 | 生产环境基础保障 |
| **4.3** 系统日志查询 | 开发和初期排障必备 |

### P1 — 重要功能（第二阶段交付）

| Story | 理由 |
|:--|:--|
| **1.2** 班级薄弱概览 | 教师高频使用场景 |
| **1.3** 知识图谱可视化 | 降低教师认知门槛的关键功能 |
| **1.7** 教学建议生成 | 打通"分析→行动"的价值闭环 |
| **3.3** 实体对齐审核 | 数据质量保障 |
| **3.5** 剪枝策略配置 | "任务驱动剪枝"是可配置的系统策略，非一次性硬编码；多任务类型需不同剪枝参数 |
| **3.6** 权重更新规则配置 | "动态更新"是可配置的业务规则，衰减参数和行为削减逻辑不能硬编码 |
| **3.8** 知识体系管理 | 知识点"图钉"节点的体系化，前置依赖关系是剪枝和归因的基础数据 |

| **6.1** 访问行为审计 | 合规基础，上线前必备 |
| **6.2** 归因回放 | 核心功能的可解释性保障 |
