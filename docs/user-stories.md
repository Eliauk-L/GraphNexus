## US-01 · 管理员（10 个 Story）

### Story 1.1 — 教辅 PDF 上传与图谱构建

| 维度 | 说明 |
|:--|:--|
| **角色** | 管理员 |
| **场景** | 学校采购了新的教辅资料，需要将其导入系统供教师使用 |
| **功能** | **（1）PDF 上传与管理**：支持单个上传和批量上传（一次拖入多份 PDF），上传前自动检测文件格式和大小（超过限制提示压缩），支持查看已上传文档列表（按上传时间、学科分类、处理状态排序），支持重新上传覆盖旧版本文档、删除已上传文档并级联清除其图谱数据；**（2）自动化处理流水线**：上传后系统自动执行——版面分析（识别正文/标题/表格/公式区域）→ 实体抽取（提取概念、公式、定理、定义等知识点实体）→ 关系抽取（识别知识点之间的引用、推导、包含、前置依赖关系）→ 图谱导入 Neo4j（创建实体节点和关系边，关联文档来源元数据）；**（3）处理结果反馈**：处理完成后返回构建结果摘要——抽取实体数量与类型分布、关系数量与类型分布、处理耗时、置信度分布（高/中/低置信度实体占比），低置信度实体列表供管理员人工复核；**（4）解析失败处理**：对解析失败的 PDF（如扫描版图片 PDF 无 OCR 识别层、加密 PDF）自动标记失败原因，提示管理员提供可替代的文本版或手动录入关键知识点 |
| **目的** | 将 PDF 入库流程自动化，管理员只需"上传 + 确认"，无需理解底层图谱技术 |

### Story 1.2 — 学生主数据维护与成绩导入

| 维度 | 说明 |
|:--|:--|
| **角色** | 管理员 |
| **场景** | 学期初有新学生入学或班级调整，学期中有学生转学/休学，每次考试后教务处提供全年级成绩表——学生作为宽图谱的核心"图钉"节点，其主数据的准确性直接影响图谱质量 |
| **功能** | **（1）学生主数据维护**：支持学生信息的新增（姓名、学号、班级、入学年份）、批量更新（如分班调整后批量修改班级字段）、状态标记（在读/休学/转学/毕业），离校学生数据保留但标记为归档状态，不再参与权重计算；**（2）成绩 CSV 导入与事件化**：上传 CSV 文件 → 系统校验字段格式（学号、科目、知识点、得分等）→ 将每行记录转化为事件节点并自动关联已有学生与知识点 → 返回导入结果摘要（成功条数、失败条数、异常记录及原因）；**（3）导入冲突处理**：CSV 中的学号在系统中不存在时，提示管理员选择"自动创建学生节点"或"标记为异常跳过" |
| **目的** | 将学生从"CSV 中的一行数据"提升为可主动维护的主数据实体，保障这一"图钉"节点的数据完整性和生命周期管理，同时保留批量导入的零代码效率 |

### Story 1.3 — 作业数据导入与事件化

| 维度     | 说明                                                         |
| :------- | :----------------------------------------------------------- |
| **角色** | 管理员                                                       |
| **场景** | 学校或年级统一布置的大型作业（如假期作业、专项练习册）由教务系统集中管理，管理员需要将这些作业记录批量导入系统——与考试成绩类似，这类年级级统一作业的数据由教务处统一提供，适合管理员批量处理 |
| **功能** | **（1）作业数据批量导入与事件化**：上传作业记录 CSV 文件 → 系统校验字段格式（学号、作业名称/编号、关联知识点、提交状态、批改结果、得分、教师评语等）→ 将每行记录转化为"作业事件节点"（区别于考试事件，事件类型标记为"作业"），通过外键关系自动关联已有学生节点与知识点节点 → 返回导入结果摘要（成功条数、失败条数、异常记录及原因）；**（2）作业事件节点属性**：每个作业事件节点包含——作业类型（日常练习/专项训练/章节测验）、关联知识点（支持一道作业题关联多个知识点）、批改结果（正确/部分正确/错误/未提交）、教师标注的错题原因分类（计算错误/概念混淆/方法缺失/粗心）等结构化字段，支持后续在权重更新规则中被引用；**（3）批量与增量导入**：支持按班级批量导入（一次导入全班 45 名学生的某次作业记录）和增量追加（后续补充批改结果或补交记录），增量导入时系统自动匹配已有作业事件节点并更新其属性，不产生重复节点；**（4）作业数据质量校验**：校验逻辑包括——学号是否已存在于系统中（不存在时复用学生主数据导入的冲突处理机制）、作业关联的知识点名称是否能匹配到系统知识体系中的已有知识点（不匹配时提示确认或跳过）、同一学号同一作业是否存在重复提交记录 |
| **目的** | 将教务系统中的年级级统一作业数据结构化入库，管理员作为学校官方数据的统一入口，高效完成批量导入，与教师端的班级作业上传（2.11）形成互补——管理员覆盖年级统一作业，教师覆盖日常班级作业 |

### Story 1.4 — 实体对齐审核与管理

| 维度 | 说明 |
|:--|:--|
| **角色** | 管理员 |
| **场景** | 不同来源的数据中，同一个知识点可能有不同的表述（如"二次函数" vs "一元二次函数"），系统自动合并后需要人工确认 |
| **功能** | **（1）对齐任务列表**：系统基于实体名称相似度（编辑距离、语义 Embedding 余弦相似度）和属性重叠度自动生成候选匹配对，按置信度分三档展示——高置信度（> 0.9，建议自动合并，展示供管理员抽查）、中置信度（0.6-0.9，需管理员逐条确认）、低置信度（< 0.6，仅作提示，由管理员手动判定）；**（2）逐条审核操作**：每条匹配对并排展示两个实体的完整信息（名称、来源文档/CSV、关联关系数、最近更新时间），管理员逐一执行确认合并（保留主实体、将副实体的关系迁移至主实体后删除副实体）、驳回（标记为不同实体，加入白名单避免再次建议合并）、手动修正（选择保留哪个名称、或输入自定义合并后名称）；**（3）批量操作**：支持按置信度区间、实体类型、来源批量选中匹配对，一键批量确认/批量驳回，批量操作前展示影响面摘要（将合并多少对、影响多少条关系）；**（4）合并历史与回滚**：记录每次实体对齐操作的完整日志（操作时间、操作人、合并前实体状态快照），支持在发现错误合并后一键回滚——恢复被删除的副实体、还原被迁移的关系 |
| **目的** | 在自动化效率与数据准确性之间取得平衡，关键合并不交给黑盒 |

### Story 1.5 — 剪枝策略配置与管理

| 维度 | 说明 |
|:--|:--|
| **角色** | 管理员 |
| **场景** | 系统支持多种任务类型（归因分析、复习推荐、班级概览等），不同任务对子图的深度、广度、权重阈值要求不同——归因分析需要追溯深层前置依赖链，复习推荐则需要聚焦近期薄弱知识点。需要为每种任务类型配置和调优独立的剪枝策略 |
| **功能** | **（1）策略模板管理**：为每种任务类型（归因分析 / 复习推荐 / 班级概览）配置独立的剪枝策略参数——最大跳数（深度，如归因分析 3 跳、复习推荐 2 跳）、每跳最大邻居数（广度，如每跳保留 Top-K 个最强关联邻居）、关系权重阈值（低于该值的边被剪掉，如仅保留权重 > 0.3 的掌握关系）、关系类型过滤（如归因分析保留"掌握""前置依赖""同知识点"，排除"同班同学"等弱相关关系）；**（2）策略对比测试**：选择同一查询目标，使用 A/B 两种策略分别生成子图，系统对比输出节点数、关系数、LLM Token 消耗量，辅助管理员判断策略优劣；**（3）策略版本管理**：每次修改策略自动保存历史版本，支持查看变更 Diff 和回滚到任意历史版本 |
| **目的** | 将"任务驱动剪枝"从硬编码逻辑提升为可配置、可对比、可回滚的系统策略，让不同任务使用最优剪枝参数，在子图信息完整度与 LLM Token 成本之间取得平衡 |

### Story 1.6 — 权重更新规则配置

| 维度 | 说明 |
|:--|:--|
| **角色** | 管理员 |
| **场景** | 学生与知识点的"掌握"关系权重不是静态的——随着时间推移旧成绩应自然衰减，新的考试/作业数据应及时增强或削弱权重。不同的学科和年级可能需要不同的衰减节奏（如小学数学遗忘慢、高中物理遗忘快），不能将衰减公式硬编码在代码中 |
| **功能** | **（1）时间衰减规则配置**：定义全局或按学科的衰减参数——衰减曲线类型（指数衰减 / 线性衰减 / 阶梯衰减）、半衰期（如"数学知识点 90 天不再练习则权重减半"）、衰减计算周期（如每天凌晨执行、每周一执行）；**（2）行为事件权重规则配置**：定义什么事件触发多大权重的调整——正确作答（权重 +Δ，如 +0.05）、错误作答（权重 -Δ，如 -0.08）、课堂表现优秀（权重 +Δ，如 +0.03）、长时间未接触（自动衰减，按上方规则执行），支持按事件类型分别设置调整幅度和生效范围（仅影响该知识点 / 影响所有前置依赖知识点）；**（3）规则模拟与影响预估**：选择一条配置中的规则，在指定学生/班级范围上模拟执行，系统输出将有多少条"掌握"关系权重发生变化、变化分布（增强/削弱的比例），辅助管理员评估规则变更的影响范围，避免衰减过激导致全校数据失真；**（4）权重变更日志**：每次权重更新（无论由定时任务还是事件触发）自动记录：变更时间、变更前后的权重值、触发原因（具体衰减规则 ID 或事件 ID）、操作来源（系统自动 / 管理员手动修正） |
| **目的** | 将"动态更新"支柱从硬编码脚本提升为可配置、可模拟、可追溯的业务规则引擎，让权重变化有理有据，既反映真实学习规律，又经得起审计追溯 |

### Story 1.7 — 宽图谱全局浏览

| 维度 | 说明 |
|:--|:--|
| **角色** | 管理员 |
| **场景** | 随着 PDF 教辅和成绩数据不断入库，宽图谱持续增长。管理员需要直观了解当前图谱的全局结构——哪些知识点是核心枢纽、知识结构是否合理、是否存在数据稀疏的"冷区"——而不是从统计数字中猜测图谱形态 |
| **功能** | **（1）全局拓扑概览**：以力导向布局展示宽图谱的全貌——节点为知识点/学生/事件实体，边为它们之间的关系，节点大小反映 PageRank 或度中心性，支持缩放、拖拽、按实体类型筛选显示；**（2）聚类与社区发现**：按学科、年级或自动检测的社区结构对图谱着色分组，直观展示不同学科知识点的聚集程度和跨学科桥接节点；**（3）聚焦与下钻**：点击任意节点展开其邻域子图，查看该节点的关联实体与关系权重；支持按学科/年级/实体类型一键聚焦，过滤无关节点；**（4）图谱健康度度量**：展示全局图谱指标——节点数/关系数、平均度、连通分量数、孤立节点列表（未被任何关系连接的知识点/学生）、关系密度热力图（按学科区域显示边的稠密程度），辅助管理员识别数据盲区 |
| **目的** | 为宽图谱这一核心数据资产提供一张"活地图"——从统计数字（1.5）升级为可交互的全局可视化视图，让管理员能够发现知识结构问题（如某学科知识点之间缺乏前置依赖关系）、定位数据稀疏区域，指导后续的数据补充和实体对齐工作 |

### Story 1.8 — 知识体系管理

| 维度 | 说明 |
|:--|:--|
| **角色** | 管理员 |
| **场景** | 知识点是宽图谱的另一个核心"图钉"节点。PDF 文档解析能自动抽取知识点实体，但知识点的层级结构（如"函数 → 二次函数 → 配方法"）、学科归属、以及知识点之间的前置依赖关系（学 A 之前必须先掌握 B），需要人工定义和维护，不能完全依赖自动抽取 |
| **功能** | **（1）知识点分类树管理**：支持多级树形结构的创建与编辑——学科（数学/物理/...）→ 一级模块（代数/几何/...）→ 二级章节（函数/方程/...）→ 具体知识点（二次函数），支持拖拽调整层级、批量导入分类模板；**（2）前置依赖关系定义**：在教育学中知识点之间存在严格的学习路径依赖——如"配方法"的前置依赖是"一元二次方程"和"完全平方公式"。管理员能为任意知识点指定其前置依赖知识点，系统自动构建"知识依赖有向图"并在宽图谱中与对应实体节点关联；**（3）知识点节点管理**：查看所有知识点实体列表（含来源——自动抽取/人工创建/CSV 导入）、编辑知识点名称与描述、合并重复知识点（与实体对齐审核功能联动）、标记废弃知识点（不再纳入剪枝和权重计算）；**（4）知识体系完整性检查**：系统自动检测分类树中的空节点（有分类无知识点）、孤立知识点（未被任何分类树层级覆盖）、循环依赖（A 依赖 B、B 依赖 A），生成完整性报告 |
| **目的** | 将知识点从"被抽取的标签集合"提升为具有层级结构、学科归属和学习路径依赖的有序知识体系，让教师的归因分析（如"学生缺少配方法前置知识"）有据可依，让剪枝策略（如"沿前置依赖链上溯 2 跳"）有图可循 |

### Story 1.9 — 考试-题目-知识点关联模型定义

| 维度 | 说明 |
|:--|:--|
| **角色** | 管理员 |
| **场景** | 成绩导入（1.2）、作业导入（1.3）、课堂测验导入（2.10）都需要将"考试/测验 → 题目 → 知识点 → 学生得分"这一链条结构化入库。如果各导入 Story 各自定义数据结构，会导致数据模型不统一、归因分析缺乏一致的证据链基础。需要在数据导入之前，先明确这一核心关联模型 |
| **功能** | **（1）试卷结构定义**：管理员可定义试卷/作业的层级结构——考试名称 → 大题列表 → 小题列表，每道小题可关联 1 个或多个知识点（从知识体系分类树中选择），支持多对多关系（同一知识点可出现在多道题中，同一道题可考察多个知识点）；**（2）得分粒度配置**：定义系统中得分记录的最小粒度——选项 A：仅记录总分（实现简单，但无法做题目级归因）、选项 B：记录每题得分（推荐，支持题目级正确率分析）、选项 C：记录每个知识点维度的得分（需题目-知识点映射后自动计算），粒度选择影响后续权重计算的精细程度；**（3）得分分配规则**：当一道题关联多个知识点时，定义得分如何分配到各知识点——策略 A：平均分配（题得分 10 分关联 2 个知识点则各得 5 分）、策略 B：按管理员设定的权重比例分配、策略 C：全部计入（每个知识点均记录完整得分，可能重复计算但保留最完整信息），分配规则全局生效或按学科/考试类型分别设置；**（4）模型一致性校验**：CSV 导入时系统自动校验数据结构是否符合定义的模型——题目数量是否匹配、知识点名称是否可映射到知识体系、得分格式是否合法，不符合的记录标记为异常并在导入结果中列出具体原因 |
| **目的** | 为系统的"知识点-考试/测验-题目-得分"关系建立统一的数据模型基础，确保事件导入（1.2/1.3/2.10）、权重计算（1.7）、归因分析（2.1）使用一致的数据结构定义，避免各模块各自为政导致数据碎片化 |

## US-02 · 教师（11 个 Story）

### Story 2.1 — 单学生薄弱点归因查询

| 维度 | 说明 |
|:--|:--|
| **角色** | 教师 |
| **场景** | 批改作业时发现学生A连续多次在二次函数题目上出错，想了解根本原因是什么 |

### Story 2.11 — 班级作业数据上传与事件化

| 维度 | 说明 |
|:--|:--|
| **角色** | 教师 |
| **场景** | 教师在日常教学中布置并批改作业后，需要将学生的作业表现数据录入系统——作业数据是教师教学过程中自然拥有的过程性评价数据，与考试成绩（总结性评价）不同，它能更及时、更细粒度地反映学生的知识掌握变化。教师作为这些数据的直接生产者和拥有者，应能独立上传自己任教班级的作业记录；年级或学校统一布置的大型作业则由管理员通过教务系统批量导入（1.3） |
| **功能** | **（1）作业数据上传**：教师通过简化的上传流程录入作业数据——选择任教班级 → 输入作业名称/编号 → 批量输入或导入 CSV 格式的学生作业记录（提交状态、批改结果、得分、错题标注等），系统自动校验教师身份与班级归属，将每行记录转化为"作业事件节点"并关联已有学生节点、知识点节点和对应的考试/测验节点，知识点从管理员定义的知识体系中选择（未匹配的标记为"待确认"）；**（2）作业事件节点属性**：每个作业事件节点包含——作业类型（日常练习/专项训练/章节测验）、关联知识点（支持一道作业题关联多个知识点）、批改结果（正确/部分正确/错误/未提交）、教师标注的错题原因分类（计算错误/概念混淆/方法缺失/粗心）等结构化字段，支持后续在权重更新规则中被引用；**（3）增量追加**：支持后续补充批改结果或补交记录，增量上传时系统自动匹配已有作业事件节点并更新其属性，不产生重复节点；**（4）即时反馈**：上传完成后系统立即展示本次作业的班级整体表现——提交率、各批改结果分布、关联知识点的班级平均掌握度变化，帮助教师快速了解班级作业情况；**（5）权限与范围限制**：教师只能上传自己任教班级的作业数据，系统自动校验教师身份与班级归属，上传记录对管理员可见以便审计追溯，作业数据进入图谱后参与权重计算和归因分析 |
| **目的** | 让教师作为作业数据的直接生产者，拥有独立的数据上传通道——相比管理员批量导入（1.3），教师端更强调快速录入和即时反馈，使教师在批改作业后能迅速完成数据入库并获得班级学情反馈，将教师日常的作业批改行为转化为宽图谱中的结构化事件节点，确保数据的及时性和准确性 |

| **功能** | **（1）用户行为漏斗**：以漏斗图展示用户从注册 → 首次查询 → 高频使用（月查询 > 10 次）→ 核心用户（周查询 > 3 次）的转化率，每层标注流失人数和流失率，支持下钻查看各层的用户名单和行为明细；**（2）功能使用分布**：以柱状图 + 饼图展示各功能模块的使用频次占比——归因查询 / 班级概览 / 图谱可视化 / 教学建议 / 报告导出 / 复习推荐，标注"零使用率功能"（上线超过 30 天但从未被使用的功能）和"明星功能"（使用频次最高的前 3 个功能）；**（3）用户留存与活跃度**：展示用户留存率曲线（次日留存/7 日留存/30 日留存），按用户群体分组对比（教师 vs 学生 vs 管理员），定义高频用户（月活跃 > 20 天）、普通用户、沉默用户（连续 30 天无任何操作），展示各组占比和变化趋势；**（4）会话行为深度**：统计单次会话的平均停留时长、平均操作步数、平均查询深度（追问次数），对比"高留存用户"和"流失用户"的行为差异，提取能预测留存的关键行为特征 |
| **目的** | 发现功能短板（某功能没人用）、识别流失风险，驱动产品迭代优先级 |

### Story 5.4 — 系统价值报告生成

| 维度 | 说明 |
|:--|:--|
| **角色** | 运营人员 |
| **场景** | 季度结束，需要生成一份面向校领导或投资方的系统价值报告 |
| **功能** | **（1）报告模板管理**：提供多种预设报告模板——月度运营简报（1-2 页，适合管理层快览）、季度深度报告（5-10 页，包含详细分析和案例）、年度价值报告（10-15 页，面向校领导/投资方），每种模板预定义章节结构和数据来源，支持运营人员自定义模板（拖拽图表组件、编辑文字段落）；**（2）自动化数据填充**：选择报告模板和时间范围后，系统自动从各运营仪表盘拉取最新数据填充图表和指标卡片——使用量趋势、文档处理增量、知识点覆盖变化、用户活跃度变化、典型案例数据（如"过去一季度全班薄弱知识点平均减少 12 个"），支持手动调整报告中的数据和文案以突出特定叙事；**（3）案例管理**：维护一个"成功案例库"——教师使用系统后的教学效果反馈（如某班级经过系统辅助后特定知识点平均掌握权重提升幅度、薄弱学生数下降比例），运营人员可选择性插入典型案例到报告中；**（4）导出与分发**：支持导出为 PDF（固定排版印刷级质量）、PPT（可编辑幻灯片，适合汇报演示）、在线链接（含交互式图表，支持浏览器查看），配置定时自动生成和邮件分发（如每季度末自动生成季度报告发送给指定收件人列表） |
| **目的** | 将运营数据转化为业务叙事，支撑续费决策、预算申请和对外宣传 |

## US-06 · 审计人员（4 个 Story）

### Story 6.1 — 数据访问行为审计

| 维度 | 说明 |
|:--|:--|
| **角色** | 审计人员 |
| **场景** | 收到投诉或定期审计时，需要追溯"谁在什么时间查看了哪个学生的什么数据" |
| **功能** | **（1）访问日志全量检索**：以表格展示每次数据访问事件的完整信息——操作时间（精确到秒）、操作者身份（教师/管理员/其他，含姓名和角色）、操作类型（查询学生归因报告 / 导出报告 / 查看班级概览 / 下载图谱数据 / 其他）、目标学生 ID 及姓名、操作来源 IP 和终端信息（浏览器/App 版本）、返回结果类型和摘要（如"返回了学生A在数学学科的归因分析报告"），支持多条件组合搜索和模糊匹配；**（2）敏感操作标记**：系统自动对敏感操作类型打标——批量导出（单次导出超过阈值数量的学生报告）、非任教范围查询（教师查询非自己任教班级的学生）、非工作时间访问（深夜/周末的查询操作），以橙色/红色标签高亮，便于审计人员快速聚焦高风险行为；**（3）用户行为画像**：选择任一操作者，系统生成其操作行为时间线——某教师在过去 N 天内查询了哪些学生、导出/分享了哪些报告、操作频率分布（按小时/天的热力图），异常行为模式自动标注（如"该教师过去 7 天查询学生总数是全校平均值的 4.2 倍"）；**（4）审计记录导出与存证**：支持将当前筛选结果导出为 CSV（用于 Excel 分析）或 PDF（含电子签名存证），支持将审计记录按周期自动归档到外部存储（如 OSS），满足长期留存合规要求（如《个人信息保护法》要求日志保存不少于 6 个月） |
| **目的** | 实现"每一次数据访问都有迹可循"，满足《个人信息保护法》对敏感个人信息处理的审计追溯要求 |

### Story 6.2 — 图谱状态快照与归因回放

| 维度 | 说明 |
|:--|:--|
| **角色** | 审计人员 |
| **场景** | 某次归因分析的结论受到质疑（如家长投诉"系统把我孩子错误标记为薄弱"），需要回放当时的决策过程 |
| **功能** | **（1）决策快照自动保存**：每次归因查询自动保存完整的决策上下文——剪枝前原始图谱的局部范围（查询起始节点 + K 跳邻域的全部节点与关系）、剪枝后的子图（展示哪些节点/边被保留、哪些被剪掉及剪掉原因）、应用的剪枝策略配置快照（策略名称、版本号、所有参数值）、LLM 输入 Prompt 完整文本（含变量渲染后内容）和模型响应的完整输出，以上全部内容以不可篡改的格式（哈希链或只读标记）存储；**（2）决策链可视化回放**：审计人员输入归因记录 ID，系统以分步动画形式回放完整决策链——第 1 步：展示原始子图范围及过滤前的关系网络 → 第 2 步：逐步展示剪枝过程（哪条边因权重 < 阈值被剪掉、哪种关系类型被过滤规则排除） → 第 3 步：展示送入 LLM 的剪枝后子图和渲染后的 Prompt → 第 4 步：展示 LLM 输出结果及系统如何将其格式化为主报告，每一步均可暂停检查中间数据；**（3）可复现性验证**：审计人员可点击"重新执行"按钮，使用快照中保存的相同子图和 Prompt 模板、但可选使用当前最新模型或当时的模型版本，重新调用 LLM 生成结果，与原始结果并排对比，标注新结果与原始结果的差异（引用的证据节点是否一致、薄弱根因排序是否变化、是否有新的推断出现）；**（4）归因记录检索**：支持按学生、知识点、时间范围、归因结论关键词（如"配方法"）、置信度等级等多维条件检索历史归因记录，查看某学生"被分析的历史"——过去被哪些教师查询过、每次归因的结论摘要和变化趋势 |
| **目的** | 保障 AI 归因的**可解释性与可复现性**——同一图谱状态 + 同一参数，必须产生一致的结论。系统判断不能被当作不可质疑的黑盒 |

### Story 6.3 — 数据变更追溯

| 维度 | 说明 |
|:--|:--|
| **角色** | 审计人员 |
| **场景** | 发现某学生的知识点掌握权重出现异常波动，需要追溯到是哪条数据录入或哪次更新导致的 |
| **功能** | **（1）变更历史全链路追溯**：以"学生 + 知识点"或"学生 + 时间范围"或"触发事件批次"为入口，展示该实体/关系的完整变更历史时间线——每次变更的时间戳、变更前后值（如"掌握权重 0.45 → 0.37"）、变更幅度和方向（+/- 数值）、触发变更的源事件详情（事件类型+关联的原始数据 ID，如"第 3 次月考·数学·第 8 题·得分 0"）、操作来源（系统自动 / 管理员手动修正 / 定时任务批量更新），支持展开源事件的原始 CSV 行数据或衰减规则配置详情；**（2）变更影响链路分析**：对单次变更，系统展示其影响传播链——如"一次数学考试中二次函数题目答错 → 二次函数掌握权重降低 → 二次函数的前置依赖知识点（一元二次方程）的间接影响权重也被微调（配置了级联传播）"，以有向图展示变更从源头事件到受影响节点的传播路径；**（3）异常波动检测**：系统自动检测异常权重波动——某学生在短时间内（如 24 小时内）某个知识点的权重变化幅度超过阈值（如 ±0.3）、某批次操作导致大量关系权重同时变化（如一次错误配置的衰减规则误更新了全校数据），标记为"待审计异常事件"推送到审计人员工作台；**（4）变更统计与报表**：按时间范围统计变更总量——各事件类型的变更次数分布、各操作来源的变更占比、Top-N 频繁变更知识点和 Top-N 频繁被修正的学生，生成"数据变更健康度报告"（变更来源分布是否合理、手动修正是否过度频繁暗示数据质量问题） |
| **目的** | 确保每一次数据变更都有明确的"责任人 + 原因"，防止数据篡改无从查证 |

### Story 6.4 — 合规规则配置与自动审查

| 维度 | 说明 |
|:--|:--|
| **角色** | 审计人员 |
| **场景** | 不希望每件事都手动查——系统应该能按预设规则自动发现和告警异常行为 |
| **功能** | **（1）合规规则库管理**：提供内置的预定义规则模板和自定义规则编辑器——每条规则包含触发条件（支持组合条件：操作者角色 + 操作类型 + 目标数据类型 + 频次/数量阈值 + 时间窗口）、风险等级（高风险/中风险/低风险）、规则启用状态和生效范围（全局/指定学校/指定用户角色），规则变更自动记录审计日志；**（2）自动扫描与告警**：系统以预设频率（实时/每小时/每天）自动扫描全量操作日志，匹配合规规则后生成"异常行为事件"——包含事件详情（触发规则、匹配的操作记录摘要、操作者、风险等级）、自动关联相关的历史审计记录（该操作者过去 30 天的同类行为统计），高风险事件实时推送通知给审计人员和相关管理者；**（3）事件处置工作流**：审计人员在异常行为清单中逐条处理——标记处理状态（待处理 / 调查中 / 已确认违规 / 已排除误报 / 已处置），填写调查结论和处置措施（如"已联系该教师确认属于年级教研需要，已调整其临时查询权限""确认违规导出，已收回导出权限并通报年级组长"），支持添加内部备注和上传调查附件（如教师的情况说明邮件截图）；**（4）合规态势总览**：以仪表盘展示当前合规健康度——各风险等级的异常事件数量及趋势、Top-N 高频违规用户、Top-N 高频触发规则（提示哪些规则阈值可能需要调整或哪些行为确实泛滥）、平均事件处置周期、待处理事件积压量，支持定期生成合规态势报告用于管理层汇报和监管报备 |
| **目的** | 将审计模式从"被动响应投诉"升级为"主动发现风险"，降低合规事故概率 |
