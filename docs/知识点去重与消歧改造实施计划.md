# GraphNexus 知识点去重与消歧改造实施计划

> 状态：实施方案，尚未修改业务代码或数据  
> 日期：2026-09-20  
> 范围：教材抽取、成绩导入、知识点融合、教师审核、图谱查询、文档删除与回滚

## 1. 目标与验收口径

将每条来源中的知识点先作为独立证据保存，再解析到稳定的规范知识点。解析过程依次执行“学科、学段、章节召回 → 多特征评分 → 自动合并／教师审核／保持独立”。任何合并均能说明候选从哪里来、各项分数是多少、由哪个模型或教师决定，以及怎样撤销。

本次改造的验收条件：

1. 同学科同名但含义不同的知识点，不因名称相同直接复用节点；跨学科、明确冲突的学段不得自动合并。
2. 同义异名知识点能在增量构建时召回并评分；章节相近但概念不同的知识点保持独立。
3. 高分且无冲突的候选自动合并；中间分数生成教师待审任务；低分保留独立。阈值从版本化标注集校准，不以现有字符 Jaccard `0.5` 直接上线。
4. 每条来源记录及每次决策可查询 `canonicalKpId`、`alias`、`sourceDocument`、`modelVersion`、`mergeRunId`，并展示特征分、阈值、审核人和时间。
5. 回滚后，规范映射、来源关系、派生关系及受影响的掌握度恢复到目标运行之前；删除一份教材不会删除其他文档或考试仍在使用的规范知识点。

## 2. 现状与需要先处理的问题

| 位置 | 现状 | 对本需求的影响 |
|---|---|---|
| `ConstructionServiceImpl.phase1_build()` | 文档 KP 按同学科同名直接复用已有 ID；抽取时生成的边仍引用原临时 ID | 消歧前已发生合并，且复用后关系端点可能失配 |
| `ConstructionGraphRepository.findOrCreateKnowledgePoint()` | 成绩 KP 按名称和学科 `MERGE` | 成绩侧同名异义也没有学段、年级、章节约束 |
| `FusionServiceImpl.fuseIncremental()` | 以本次 `kpNames` 查询候选 | 异名同义的现有 KP 无法进入候选集 |
| `FusionGroupBuilder` / `FuzzyMatchStrategy` | 同名无条件合并；其余按字符 Jaccard 及并查集聚类 | 缺少语义、年级、章节、邻居特征；并查集可能产生链式误合并 |
| `ExtractionRawResult` / `ExtractionService` | KP 有 `gradeLevel`；分类有层级，但所有 KP 默认挂到最后一个分类 | 章节路径不可靠，不能直接用于召回或评分 |
| `FusionRollbackService` / `fusion_log` | 合并组中的 `redirectedEdges` 当前为空，`mastersSnapshotJson` 写成 `[]`；回滚删除目标 KP 后只重建源 KP | 当前日志不能支撑精确回滚；API 描述的限制也未在服务中完整校验 |
| `ConstructionGraphRepository.deleteByDocumentId()` | 按节点的单个 `documentId` 执行 `DETACH DELETE` | 共享规范 KP 被某文档覆盖来源后，删除该文档可能误删共享节点 |
| `MastersRecalculationService.findKpId()` | 按成绩中的 KP 名称再次查图 | 别名和同名异义无法稳定对应掌握度 |

代码入口：`src/main/java/com/graphnexus/application/graph/construction/`、`src/main/java/com/graphnexus/application/analysis/fusion/`、`src/main/java/com/graphnexus/infrastructure/neo4j/repository/`。现有融合管理页只展示执行、状态及回滚，需要单独增加教师候选审核视图。

## 3. 目标数据模型

### 3.1 来源记录与规范节点分离

在 Neo4j 保留现有 `KnowledgePoint` 作为**规范概念**，新增 `KpMention` 作为一次教材抽取或成绩导入得到的**来源记录**：

```text
(Document/Exam)-[:HAS_KP_MENTION]->(KpMention)
(KpMention)-[:RESOLVES_TO]->(KnowledgePoint)
```

`KpMention` 至少保存：

| 字段 | 含义 |
|---|---|
| `mentionId` | 来源记录稳定 ID；同一来源重试采用确定性的幂等键 |
| `alias` | 来源中的原始名称，保留原文；另存规范化名称用于检索 |
| `description` | 来源描述或考试知识点说明；缺失显式标记 |
| `subjectId`, `stage`, `grade` | 标准学科、学段和年级；原始值同时留存以便核对 |
| `chapterPath` | 稳定的章节 ID 路径与显示路径；未知时为空，不猜测 |
| `sourceDocument` | 教材 ID；考试来源使用 `sourceType=EXAM` 加 `sourceExamNo`，不得伪造教材 ID |
| `modelVersion` | 抽取模型或导入解析器版本；历史数据记 `legacy-unknown` |
| `canonicalKpId` | 当前解析到的规范 KP ID；待审核时可为空或指向暂存独立 KP |
| `mergeRunId` | 最后一次改变其规范映射的运行 ID；未合并时为空 |

`KnowledgePoint.id` 继续作为稳定业务标识，并显式保存同值的 `canonicalKpId` 供接口使用。规范节点不再用单个 `documentId` 表达来源；其 `aliases` 是从有效 `KpMention.alias` 和教师维护别名派生的集合。保留 `fusionSource` 仅作兼容展示，不作为判定依据。

原始关系须能追溯到 `mentionId` 或来源证据 ID。`ALIGNED_TO`、`PREREQUISITE_OF`、`TESTED` 等正式关系可投影到规范 KP，但必须记录产生它们的来源，以便撤销映射后重建受影响的关系。投影去重键至少包括“关系类型、规范起点、规范终点”；不得生成自环或把相反方向的前置边折叠。`MASTERS` 由成绩证据重算，不把它当作可直接复制的普通边。

### 3.2 审核与运行账本

在 MySQL 增加以下表；变更脚本同时维护 `src/main/resources/db/init.sql` 与 `deployment/init-sql/init.sql`，生产已有库使用独立迁移脚本，不能只改初始化文件。

| 表 | 核心字段 | 用途 |
|---|---|---|
| `kp_merge_run` | `merge_run_id`, `trigger_type`, `status`, `model_version`, `feature_version`, `threshold_version`, `graph_revision_before/after`, `started_at`, `finished_at`, `failure_reason` | 一次召回、评分和执行的运行记录；旧 `fusion_log.id` 可作为关联字段，不能混淆为来源记录 ID |
| `kp_match_candidate` | `candidate_id`, `mention_id`, `target_canonical_kp_id`, `feature_scores_json`, `total_score`, `hard_conflicts_json`, `evidence_json`, `decision_band`, `merge_run_id`, `status` | 候选及可解释评分；唯一键阻止同一运行重复建单 |
| `kp_match_decision` | `decision_id`, `candidate_id`, `action`, `actor_id`, `reason`, `decided_at`, `previous_canonical_kp_id`, `new_canonical_kp_id`, `merge_run_id` | 自动或教师决策；保留批准、拒绝、撤销历史，不覆盖旧记录 |

候选状态建议为 `PENDING → APPROVED/REJECTED → APPLIED`，失败进入 `APPLY_FAILED` 并可安全重试。已拒绝配对进入负向映射表或从决策账本提取，在版本未改变时阻止重复自动提议。`modelVersion` 对应语义模型及抽取模型时应分字段记录，API 的汇总字段可列出两者。

MySQL 和 Neo4j 没有跨库原子事务：先持久化运行与决策，再在 Neo4j 单事务应用映射和投影，最后更新 MySQL 状态；中间失败由 `mergeRunId` 驱动幂等重试或补偿。不得把 MySQL 的 `COMPLETED` 当作 Neo4j 已提交的唯一依据；完成前检查图修订号和实际映射。

## 4. 召回、评分与决策

### 4.1 候选召回

1. 标准化学科、学段、年级、章节 ID 与名称。学科为强约束；明确不同的学段默认不进入自动合并集合，跨学段复用概念只通过人工维护的显式映射处理。
2. 在同学科、同学段范围内，优先召回同章节、同父章节和相邻章节的规范 KP；再从规范名称、已确认别名和描述语义索引中补充候选。跨章节命中保留章节差异特征，不直接合并。
3. 学段或章节缺失时允许受限召回，但候选标为 `context_incomplete`，不得仅凭名称进入自动合并。每个来源记录设置候选上限与可观测的截断标记；召回为空时创建独立规范 KP，不把“无候选”当作审核完成。
4. 全量处理按学科、学段及章节分批，增量处理以新 `mentionId` 查现有规范 KP。为学科、学段、章节路径、规范名称和别名建索引，避免全学科两两比较。

需要把 `GraphConstructedEvent` 的增量载荷由 `kpNames` 扩展为来源记录 ID 集合和来源 ID。历史调用方在迁移期可保留兼容分支，但上线自动消歧前必须切换到 ID 路径。

### 4.2 特征与评分

评分输入固定为一个来源记录与一个规范 KP。建议首版权重作为离线实验起点：

```text
score = 0.30 * 名称/别名相似度
      + 0.25 * 描述语义相似度
      + 0.15 * 年级兼容度
      + 0.15 * 章节路径相似度
      + 0.15 * 邻居结构相似度
```

- 名称：全半角、空白、标点和常见公式记法归一；完全同名是强证据，**不是无条件合并指令**。保留原名称，避免数学符号归一造成异义。
- 描述语义：新增 `KpSemanticSimilarity` 接口，批量生成/读取同一 `modelVersion` 的语义表示并缓存。项目目前没有已接入的知识点向量服务，具体模型和存储在实施前用本项目标注集选型。服务不可用或版本不一致时记录缺失并转审核，不把缺失记成 0 分后直接判独立。
- 年级：使用标准年级及学段；明确冲突的年级给惩罚或否决，前后年级的正常复习关系单独标注，不由阈值猜测。
- 章节：比较稳定章节 ID 路径的最近公共祖先及距离；禁止依赖当前“所有 KP 挂最后分类”的结构。
- 邻居：比较已确认的前置/后续概念、类别和实体对齐，关系类型及方向必须一致。稀疏图记录“证据不足”，不能直接等同结构不相似。

先执行学科/学段强冲突、已拒绝配对、前置关系自环风险等规则，再计算总分。评分结果保存五项分数、归一化输入摘要、证据 ID、模型版本及规则命中原因。候选之间不能用单链接并查集直接闭包合并；若一个来源命中多个规范点，或合并会使组内成员互相冲突，转教师审核。

### 4.3 三段决策

初始实验阈值可设为 `T_auto=0.92`、`T_review=0.75`，仅用于标注集校准：

| 条件 | 处理 |
|---|---|
| `score ≥ T_auto`，无硬冲突、上下文完整且规范组一致 | 自动批准并应用映射 |
| `T_review ≤ score < T_auto`，或信息不足、多目标冲突、结构冲突 | 建教师审核任务，暂时保持独立身份 |
| `score < T_review`，且无其他待审候选 | 保持独立，记录本次低分依据 |

按学科和学段标定阈值，固定标注集版本与特征版本。上线门槛优先约束**自动合并精确率**，同时观察待审量、漏召回率和误合并导致的下游诊断变化。教师批准/拒绝是训练与阈值复核的反馈，不能立即无审计地改变线上权重。

## 5. 应用流程与接口修改

### 5.1 教材和成绩入口

`ExtractionRawResult.RawKnowledgePoint` 增加可校验的章节关联（例如 `categoryIndex` 或章节 ID），并在 Prompt 中要求逐 KP 返回；校验不通过时保留“章节未知”，不默认挂到最后分类。文档元数据提供的学科、学段优先于 LLM 自报值，冲突写入质量报告。`ConstructionServiceImpl` 先写来源记录，得到 `mentionId → canonicalKpId` 映射后，再重写所有知识点关系端点并执行 `GraphQualityValidator`；禁止沿用临时 KP ID 保存边。

成绩导入也创建来源记录。CSV/Excel 只给出知识点名称而没有学段、年级或章节时，复用已有规范点必须走候选与审核流程；考试题目和 `MASTERS` 更新使用已确认的规范 ID，待审记录先保持独立，避免误归因。

### 5.2 融合与审核服务

在 `application.analysis.fusion` 拆分 `CandidateRetriever`、`KpFeatureExtractor`、`KpScorer`、`DecisionPolicy`、`MergeProjectionService`、`KpReviewService`。`FusionServiceImpl` 只编排运行状态和受影响的掌握度重算；现有 `FuzzyMatchStrategy` 可作为名称子特征保留，不再直接决定合并。`FusionGroupBuilder` 的无条件同名 pass 与并查集自动闭包在新流程启用后移除。

新增教师接口，建议放在独立的 `KpReviewController`，授予 `TEACHER`/`ADMIN`：

```text
GET  /api/v1/analysis/kp-review/candidates?status=PENDING&subject=数学
GET  /api/v1/analysis/kp-review/candidates/{candidateId}
POST /api/v1/analysis/kp-review/candidates/{candidateId}/approve
POST /api/v1/analysis/kp-review/candidates/{candidateId}/reject
GET  /api/v1/analysis/kp-review/runs/{mergeRunId}
POST /api/v1/analysis/kp-review/runs/{mergeRunId}/rollback   [ADMIN]
```

批准请求须包含目标 `canonicalKpId`、审核理由及候选版本；用乐观锁或图修订号防止教师审核期间目标已改变。拒绝请求也记录理由。前端在 `frontend/src/views/fusion/` 增加待审列表、并排证据与五项特征分、批准/拒绝操作和运行历史；原“融合管理”页可保留全量运行入口，但展示实际状态而非仅“已完成/已回滚”。

### 5.3 查询、删除和掌握度

文档图查询改为 `Document → KpMention → KnowledgePoint`，让同一规范点在多个文档中出现仍能追溯各自证据。`deleteByDocumentId()` 只删除该文档的来源记录与来源关系，再更新规范投影；只有完全无来源、无成绩引用且不受教师锁定的孤立规范点才可清理。成绩中的名称先映射为 `canonicalKpId`，`MastersRecalculationService` 不再按 `kpName` 取第一个节点。检查剪枝、查询、评测与前端图展示对 KP ID 和 `documentId` 的依赖，逐一改为规范 ID／来源关系。

## 6. 回滚设计

新流程优先**撤销映射并重建派生图**，保留不可变来源记录与历史决策，不在常规合并中硬删来源 KP。每次应用前保存受影响 `mentionId → canonicalKpId` 映射、规范节点属性、来源边、派生边键及 `MASTERS` 相关范围；记录图修订号和快照校验和。回滚生成一条新的逆向运行记录，不改写原决策历史。

仅当目标运行之后没有依赖该映射的后续合并，或后续运行已按逆序撤销时，允许回滚。Neo4j 的映射恢复与关系重建放在同一事务；MySQL 状态通过 `mergeRunId` 幂等协调。回滚结束校验节点数、来源映射、各类型边、权重及校验和。失败保持 `ROLLBACK_FAILED` 并给出可重试原因，不能把 `fusion_log.rolledBack` 提前置真。

旧 `fusion_log` 的不完整快照不可宣称支持精确回滚。迁移时先导出图备份和日志；旧运行若缺少完整边／目标属性快照，在新管理页标记为“需从备份恢复”，不得调用现有破坏性回滚逻辑。

## 7. 迁移、开关与上线顺序

| 阶段 | 主要修改点 | 交付与验收 |
|---|---|---|
| P0 基线与备份 | 冻结典型教材、考试和图快照；统计重复/同名异义样本；准备人工标注集 | 可重复的现状基线、图备份与迁移回退步骤 |
| P1 来源模型 | 新增 `KpMention`、`canonicalKpId`、章节映射和审计表；修复 KP 临时 ID 的边重映射 | 同名不再预合并；文档和考试来源均可按 ID 追溯 |
| P2 召回与打分 | 分层索引、增量 ID 事件、语义适配器、五特征评分、冲突规则 | 标注集上输出候选覆盖率和逐项评分解释；不写自动合并结果 |
| P3 审核与执行 | 三段决策、教师接口和页面、规范投影、掌握度映射 | 自动/审核/独立三路径可端到端验证；教师并发审核可处理 |
| P4 回滚与迁移 | 映射快照、逆向运行、文档删除和查询适配；历史图回填 | 新运行可精确回滚，删除来源不误删共享 KP；历史不明信息显式标记 |
| P5 灰度 | `OFF → SHADOW → REVIEW → AUTO`，按学科逐步开放 | 自动合并精确率和教师撤回率达标；异常可切回审核模式 |

回填时从现有 KP 与边生成可证明来源的 `KpMention`；来源、学段、章节或模型版本无法从数据确认的字段标为 `legacy-unknown`，这些记录不参与自动合并。回填过程幂等，采用小批次与断点记录；每批比较前后规范点数、来源数、边数和查询结果。现有 `fusion_log` 保留只读历史，新运行使用 `kp_merge_run`，避免混淆新旧回滚语义。

## 8. 必要测试与验收数据

| 场景 | 必须验证的结果 |
|---|---|
| 同名异义：同学科不同学段/章节 | 不自动合并，原文证据和冲突原因可见 |
| 异名同义：跨文档同章节 | 增量召回、正确打分并映射到同一 `canonicalKpId` |
| 链式误合并：A≈B、B≈C、A≠C | 不通过传递闭包把 A、C 合并 |
| 缺少年级/章节或语义模型不可用 | 不凭名称自动合并，进入审核或保持独立并说明原因 |
| 复用既有 KP 后写入对齐与前置边 | 所有端点均是有效规范 ID，方向、自环和重复边校验通过 |
| 教师并发批准/拒绝与重复请求 | 决策幂等；过期候选返回冲突并要求刷新 |
| 删除共享 KP 的一份来源文档 | 仅该文档证据消失，其他文档、考试和掌握度保持有效 |
| 回滚自动或教师批准的一次运行 | 来源映射、规范属性、派生边与受影响权重和运行前快照一致 |
| 跨库中途失败、重试和图状态变化 | 不报告虚假的完成/回滚成功；幂等恢复或明确阻止 |

验收报告至少给出：候选召回率、自动合并精确率、误合并数、教师待审量与处理时间、独立保留率、回滚成功率及下游诊断回归结果。测试集按教材和章节分组，避免同一章节的近重复样本同时进入调参与验收集合。

## 9. 开工前需要固定的决策

1. 知识点的“学段”和“年级”如何由教材元数据、目录与考试数据确定；缺失值不得交给模型凭空补齐。
2. 章节 ID 的权威来源及跨教材章节映射表由谁维护。章节文字路径可以展示，召回应优先使用稳定 ID。
3. 语义相似度使用的模型、部署位置、版本管理和成本上限；在标注集上确认后再固定阈值。
4. 历史融合数据的备份与停写窗口，以及无法证明来源的旧 KP 如何进入人工清理队列。

这些决策不影响 P0 基线和 P1 来源模型的准备，但应在 P2 自动评分上线前确定。
