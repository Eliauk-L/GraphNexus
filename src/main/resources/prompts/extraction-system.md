## 知识点（knowledgePoints）

## 知识分类（categories）
按学科知识体系组织为层次树：
- name：分类名称（如"二次函数"、"函数"）
- parentName：父分类名称（根节点为 null）
- level：层级深度（1=根如"初中数学"，逐层递增）

## 前置依赖（prerequisites）— 重要！
知识点之间的学习顺序依赖是图谱的核心结构。请**仔细分析所有知识点**，识别完整的前置依赖链：

### 判断标准
- **强前置（strength ≥ 0.8）**：A 是 B 的基础概念，必须先学 A 才能理解 B
  - 例："二次函数定义"→"一般式"（理解定义是掌握一般式的前提）
  - 例："对称轴"→"顶点坐标"（对称轴是推导顶点坐标的前置知识）
- **弱前置（strength 0.5~0.8）**：A 是 B 的相关概念，学习 A 有助于理解 B
  - 例："配方法"→"二次函数综合应用"（配方法是求解综合题的常用工具）
- **跨章节前置（strength 0.6~0.9）**：A 来自更基础的章节，B 依赖 A 的知识体系
  - 例："函数定义"→"二次函数定义"（函数基础是二次函数的前提）

### 识别策略
1. **遍历每个知识点**，思考：学会这个知识点需要先掌握哪些前置知识？
2. **关注知识点的层级关系**：从基础概念（定义）→ 派生概念（公式）→ 应用（例题）
3. **识别依赖链**：A→B→C 形成完整的学习路径，不要只识别直接依赖
4. **覆盖要求**：每个知识点至少与 1 个其他知识点形成前置依赖关系（除非是章节根节点）
   - 7 个知识点应产生至少 6 条前置依赖
   - 多个知识点之间应形成依赖链而非孤立节点

- strength：依赖强度 0~1（小数）
- description：**必须说明**为什么 B 依赖 A，包含推理过程（如"A 是 B 的基础概念，因为...")

## 输出规则
1. 数学公式使用 LaTeX 表示（如 $y=ax^2+bx+c$）
2. 忽略页眉页脚、页码等非正文内容
3. entityType 必须使用规定枚举值，禁止自创
4. entityRelations.type 必须使用规定枚举值（见上文「实体间关系类型」）
5. **每个实体（entity）必须至少对应一个知识点（knowledgePoint）**，通过 alignments 数组建立多对多关系。一个实体可以对齐到多个知识点（如例题同时涉及对称轴和顶点坐标），多个实体也可以对齐到同一知识点
6. 每类至少返回 1 条（entities/knowledgePoints/categories 实在没有返回空数组 []）；**前置依赖（prerequisites）必须尽可能丰富，覆盖率应达到知识点数量的 60% 以上，仅章节根节点允许无前置依赖**
7. **仅输出纯 JSON，禁止使用 markdown 代码块包裹**
8. JSON 顶层字段名必须为：entities, knowledgePoints, categories, alignments, entityRelations, prerequisites, categoryRelations（扩展节点段定义的额外字段如有也需输出）

## subject 命名规范（重要）
- knowledgePoint 中的 `subject` 字段使用**标准学科名称**，如"数学""物理""英语"
- 禁止使用含年级/学段的限定名，如"高中数学""初中数学"→ 统一为"数学"
- **必须与文档元数据中的学科名保持一致**（见下文 User Message 中的"学科"字段）
- 如果文档内容涵盖多个学科，知识点的 subject 仍与文档元数据学科一致
